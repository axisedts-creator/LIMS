Title: CR-C1-T24: name and owner of the non-prod GoTrue mail sink; staging sink vs relay (AC-21.2 vs 02-TRD s7)
From chunk: C1            To owner: C1 (lead ruling)
Type: bug
Blocking? yes - T-24 done_when "merge -> dev auto": deploy.yml's non-prod mail guard fails closed in dev/staging.
Problem: PRD AC-21.2 "Given non-prod, Then the GoTrue SMTP points to the local mail sink". 02-TRD s7 line 495 says
  prod/staging use the relay `{{ smtp_relay_fqdn }}:587`, dev the "local mail sink". (a) The spec names no variable,
  host, service or owning role for the local mail sink; T-24 used the invented name `mail_sink_fqdn` (no inventory
  sets it). (b) For staging, AC-21.2 (sink) and 02-TRD line 495 (relay) contradict.
Proposed change (exact): (a) lead names the sink variable (e.g. keep `mail_sink_fqdn` in group_vars of dev/staging)
  and the role that runs the sink; (b) rule staging = sink (AC-21.2) or relay (TRD line 495).
  deploy.yml guard "Non-prod GoTrue mail goes to the local sink" then asserts the ruled variable for the ruled envs.
Backward compatible? yes (non-prod only).
Tenant/security impact: none on RLS/PHI; a real relay from staging could mail synthetic users' addresses outward.
IRD/regulatory impact: n/a
Alternatives considered: drop the guard (loses AC-21.2 enforcement); guard on dev only (follows TRD, breaks AC-21.2).
Tests that will prove it: test_t24_cicd.py mail-sink tests, adjusted by the tester after the ruling.
