Title: CR-C1-T29c: secret id for the DR interim pgBackRest repo passphrase (02-TRD s8.2)
From chunk: C1            To owner: C1 (spec owner of 02-TRD s8.2 and infra/secrets/schema; lead ruling needed)
Type: bug
Blocking? no (T-29 dr-promote.yml uses the proposal below marked [CONV]; rename after the ruling)
Problem: AC-22.3 needs the interim repo on its own passphrase, never the repo1/repo2 one (04 I2). The pass must outlive the promoted host, so dr-promote.yml escrows it with sops in lims-secrets. 02-TRD s8.2 lists only one file per env (`prod.enc.yaml`, `staging.enc.yaml`, `dev.enc.yaml`) and no `infra/secrets/schema/*.secrets.schema.yaml` has an id for it; the schema rejects extra ids, and the pass is created at promotion time, not at provisioning.
Proposed change (exact), pick one:
  (a) add the id `pgbackrest_interim_cipher_pass` (string, optional, created by dr-promote.yml at promotion) to 02-TRD s8.2 and to every `infra/secrets/schema/<env>.secrets.schema.yaml`; the escrow then writes into `<env>.enc.yaml` with `sops --set`; or
  (b) amend 02-TRD s8.2 to allow a second per-env file `<env>.dr-interim.enc.yaml` (same age recipients as `<env>.enc.yaml`) holding only `pgbackrest_interim_cipher_pass` — matches the current playbook (dr-promote.yml, play "Interim repo - key and passphrase on the promoted host") and infra/runbooks/dr.md.
Backward compatible? yes (both additive)
Tenant/security impact: none beyond today; the value is encrypted with the env's sops rule, never on the ops host, plaintext only in memory and the promoted host's tmpfs (no_log).
IRD/regulatory impact: none
Alternatives considered: keep the pass only on the promoted host (rejected: lost with the host, interim repo unrestorable); reuse repo1/repo2 pass (rejected: 04 I2, AC-22.3).
Tests that will prove it: test_t29_dr_promote.py InterimPassEscrow (file/id names updated after the ruling); secrets schema validation test for the env files.
