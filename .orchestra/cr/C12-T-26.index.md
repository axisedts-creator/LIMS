Title: CR-C12-nnn: index for newest-first movement list by store only (listStockMovements #35 without item_id)
From chunk: C12            To owner: C12 (spec/chunks/C12-inventory/05-SCHEMA.md §2.15) / C0-0B (migration)
Type: schema
Blocking? yes (T-26 gate: TRD §12 interactive read p95 <= 300 ms at 10x seed, gate.perf "listStockMovements movements (store only, newest page)" and the 1x->10x growth check)
Problem: #35 with store_id and no item_id orders by occurred_at DESC. The only store-led ledger index is stock_movements__tenant_id_store_item__idx (tenant_id, store_id, item_id, occurred_at DESC): it cannot serve ORDER BY occurred_at without an item_id, so the query reads every movement of the store (250k rows at 10x) and top-N sorts. p95 431 ms (10x) vs 56 ms (1x); after sorting on the raw column instead of to_char: 301-337 ms (still over 300, noisy).
Proposed change (exact): CREATE INDEX stock_movements__tenant_id_store_occurred__idx ON inventory.stock_movements (tenant_id, store_id, occurred_at DESC, id DESC);
Backward compatible? yes (additive index).
Tenant/security impact: none (no RLS change, tenant_id leads).
Alternatives considered: none in application code (no other index leads with store_id and a time column); a time window default would change the API.
Tests that will prove it: gate.perf.integration.test.ts T-26 10x movements read <= 300 ms and 10x <= 6x 1x.
