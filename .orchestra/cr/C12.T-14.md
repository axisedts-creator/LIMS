Title: CR-C12-T14: CountLine contract - book_qty_snapshot not always returned (blind count); counted_qty_base allows 0
From chunk: C12            To owner: C0-0B (contracts/openapi/inventory.yaml)
Type: api
Blocking? no (T-14 ships the spec-backed behaviour; contract tests in C12 pin it)
Problem (what you cannot do today, with the user story / acceptance criterion it serves):
(a) contracts/openapi/inventory.yaml CountLine.required lists `book_qty_snapshot` (~line 11787). AC-19.x blind count (04-UI-UX S11 line 186, 07-SECURITY line 57) requires that a caller without `inventory.stock.adjust` never sees book quantities; T-14 omits book_qty_snapshot / book_qty_at_count / variance_* for such callers, so the response violates `required`.
(b) `counted_qty_base` is typed `DecimalStringPositive` (~lines 10107-10111, "server also checks > 0"). A physical count of 0 is a valid count, and TRD `uncounted_policy: 'zero'` writes 0; T-14 accepts "0".
Proposed change (exact):
- CountLine.required: remove `book_qty_snapshot`; add description "omitted when the caller lacks inventory.stock.adjust (blind count)". book_qty_at_count / variance_* stay optional.
- #66 request line `counted_qty_base`: `$ref: DecimalString` with minimum-0 note ("non-negative; 0 = counted empty") instead of DecimalStringPositive; same for CountLine.counted_qty_base.
Backward compatible? yes - only relaxes response `required` and widens request input; no other chunk consumes CountLine.
Tenant/security impact: no RLS change, no new PHI; reduces exposure (blind count). REQ-SEC per 07-SECURITY line 57.
IRD/regulatory impact: none.
Alternatives considered: always return book_qty_snapshot (breaks blind count, rejected); reject 0 counts (cannot record an empty bin; conflicts with uncounted_policy zero, rejected).
Tests that will prove it: C12 counts.contract.test.ts / counts.integration.test.ts (blind lines without book fields; counted "0" accepted) validate against the updated schema.
