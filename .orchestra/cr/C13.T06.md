Title: CR-C13-T06: give PartnerUser `mfa_enrolled` and `last_login_at` a data source
From chunk: C13            To owner: C0-0C (with C2 agreement)
Type: port
Blocking? no — C13 T06 ships with the interim behaviour below.
Problem: 02-TRD §5.2 PartnerUser lists `mfa_enrolled` and `last_login_at?` (U1/SA8 list, US-02.1/US-02.2 admin sees who is enrolled). 05-SCHEMA §3.2 partner_users has no such columns, and IdentityPort (03-IC §4.6) has no read keyed by partner membershipIds (only RequestContext.mfa for the caller, and getStaffNotificationContact for staff). C13 cannot report these values for other users.
Proposed change (exact): additive IdentityPort method
  `getPartnerMembershipStatus(ctx: RequestContext, input: { membershipIds: readonly Uuidv7[] }): Promise<readonly { membershipId: Uuidv7; mfaEnrolled: boolean; lastLoginAt: string | null }[]>;`
  Caller: C13 service with partners.partner_user.manage (same partner) or partners.partner.read (staff); unknown / non-partner membership ids omitted. Alternative: nullable mirror columns `mfa_enrolled boolean`, `last_login_at timestamptz` on partners.partner_users kept by a C2 event.
Backward compatible? yes (new port method; no wire change — fields already in PartnerUser).
Tenant/security impact: no RLS change, no PHI; tenant-scoped like every IdentityPort read (REQ-SEC-080 DTO allowlist unchanged).
Interim behaviour (until merged): `mfa_enrolled` = false, `last_login_at` omitted (services/api/src/modules/partners/mappers/partner-user.dto.ts).
Alternatives considered: hard-coded value (current interim; wrong data for enrolled admins); omitting `mfa_enrolled` (breaks the required field in partners.yaml PartnerUser).
Tests that will prove it: partner-user.test.ts U1/SA8 list returns `mfa_enrolled: true` for an enrolled membership and `last_login_at` when the fake port returns one.
