Title: CR-C13-T16: add `mapping_state` to ManifestLine.referrer so SM-2 can show "Not confirmed"
From chunk: C13            To owner: C0-0B (contracts/openapi/partners.yaml)
Type: api
Blocking? no — C13 T16 ships without the badge (interim below).
Problem: C13 04-UI-UX:214 (SM-2 lines table) requires "Doctor (+ "Not confirmed" warning badge if unmapped)" (US-06.1). contracts/openapi/partners.yaml ManifestLine.referrer (l.6495-6507) carries only `id`, `display_name`, so the staff UI cannot tell mapped from unmapped referrers.
Proposed change (exact): in ManifestLine.referrer.properties add
  mapping_state: { type: string, enum: [unmapped, mapped, rejected] }
and add `mapping_state` to `required` (values from 05-SCHEMA §3 partners.partner_referrers.mapping_state, same as 02-TRD §5.2 PartnerReferrer). Staff DTO mapper fills it from partner_referrers.mapping_state.
Backward compatible? yes for readers (additive field); partner portal DTO may omit/ignore it if lab-side mapping must stay staff-only (05-SCHEMA l.1117 "Mapping columns are staff-only").
Tenant/security impact: no RLS change, no PHI; staff-side read only (REQ-SEC-080 DTO allowlist gains one non-PHI enum).
Interim behaviour (until merged): SM-2 shows the referrer display name with no badge (apps/web/src/features/partners/components/ManifestReceive.tsx).
Alternatives considered: badge shown whenever field missing (shipped first; tells staff confirmed doctors are unconfirmed — wrong); extra SR1 lookup per manifest (N+1, needs partners.referrer.map which receivers may lack).
Tests that will prove it: t16.receive SM-2 test with one mapped and one unmapped referrer — badge only on the unmapped line; API manifest DTO test returns `referrer.mapping_state`.
