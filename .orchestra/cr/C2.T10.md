Title: CR-C2-T10: partner-session DB access path for the /me self-service operations
From chunk: C2            To owner: C0-0B (schema/RLS); C2 doc owner (05-SCHEMA §5.2, 02-TRD §5.2)
Type: schema
Blocking? yes — C2.T10 (Self service /me) for partner sessions in a live DB. Staff path is not blocked.
Problem (what you cannot do today, with the user story / acceptance criterion it serves):
02-TRD §5.2 (08 A19 D-101, 07-SECURITY AU-T20, AC-A5.2/A5.4/A6.1/A6.3/A6.4) says a partner session runs every §5.2 operation on its own records.
Under partner claims (P-16 guard; partners excluded from `__tenant` policies by `app.is_staff_or_system()`, 02-TRD §6.2) only
`sessions__select__own_user` / `__own` and `mfa_factors__*__own` are reachable (05-SCHEMA §5.2). Not reachable, but needed:
  (a) INSERT into `identity.auth_events` (`__tenant` only): events `password_changed`, `session_revoked` (self_revoke / password_change),
      `mfa_factor_removed` (self), and the P-42 `login_failed` that must survive the 401 of `changeOwnPassword`.
  (b) SELECT `core.users.email_normalized` / `display_name` (email needed for the current-password check) and
      `core.memberships.last_login_at` (02-TRD §5.2: `last_login_at` = `core.memberships.last_login_at`).
  (c) SELECT `identity.tenant_settings.password_min_length` (`__tenant` only) for AC-A6.1.
  (d) `app.enqueue_job(...)` for `identity.gotrue_signout` under partner claims (not verified; same question).
  (e) Me.roles[].role_id (RoleRef, required Uuid) has no source for a partner: the role is `partner_admin|partner_member` from the claims,
      with no `core.roles` row (02-TRD §7.1). Interim [CONV]: the membership id is returned as role_id.
Proposed change (exact): one of, owner's choice —
  1. SECURITY DEFINER functions `app.identity_self_*` (pattern of `app.identity_platform_auth_write_*`, 08 A28.1) that take tenant/user/
     membership from `app.current_*` claims only: profile read (b), min-length read (c), auth_events insert for the four event types (a); or
  2. Actor-specific policies: `auth_events__insert__own` (tenant_id = app.current_tenant_id() AND user_id = auth.uid()),
     `users__select__own`, `memberships__select__own`, `tenant_settings__select__partner` (column set limited to password_min_length).
  For (e): either allow RoleRef.role_id to be omitted for partners (OpenAPI change) or bless the membership-id convention.
Backward compatible? yes — additive (new functions/policies); (e) option "omit" is a contract relaxation.
Tenant/security impact: RLS change (new own-row policies or DEFINERs); no new PHI field; no new public surface.
Interim behaviour in code: a missing tenant_settings row fails closed (`common.internal`), never the 12 floor; partner getMe takes roles/
permissions from claims (`fixedActorPermissions('partner', partner_role)`) and reads no core role table.
Alternatives considered: running partner requests under a staff/system tx (rejected: bypasses the P-16 guard); skipping events for partners
(rejected: P-42 / AU-T22 require the failure event).
Tests that will prove it: live-DB RLS test (05-SCHEMA §11 style) — partner claims: changeOwnPassword success + wrong-password event persists
after 401; revokeOwnSession / removeOwnMfaFactor write their events; getMe returns email + last_login_at; another member's rows stay invisible.
