Title: CR-C2-T11: platform-scoped worker tasks for identity jobs + expired-token sign-out decision
From chunk: C2            To owner: C0-0D (worker core: manifest/consumer); C0-0B (worker DEFINERs); C2 doc owner (02-TRD §10)
Type: port
Blocking? yes — C2.T11 platform-kind payloads (review #1) and the expired-token sign-out path (review #3). Tenant-kind paths are not blocked.
Problem (what you cannot do today, with the user story / acceptance criterion it serves):
(1) 02-TRD §10 rows require platform-kind payloads: `identity.gotrue_signout` {user_id} (AC-A1.3 platform lock, 08 A38-2),
    `identity.send_invitation` {invitation_id} for invitePlatformStaff, `identity.remove_mfa_factors` {user_id, platform_staff_id}
    for resetPlatformStaffMfa (US-B5). Core registers every non-cron task per_tenant and `services/worker/src/core/consumer.ts` `tenantOf`
    refuses a payload without `tenant_id`; the worker also has no access path to platform rows (`identity.invitations` /
    `identity.mfa_factors` with `tenant_id IS NULL`), so the C2 default repos fail closed (common.internal -> dead letter).
(2) `identity.gotrue_signout` {user_id, tenant_id, session_id} calls signOut(stored access token, 'local'). For an idle session the stored
    access token is expired: GoTrue answers 403 bad_jwt -> 10 retries -> dead letter, while the GoTrue refresh token survives (AC-B4.1:
    revoked session must not be usable). 02-TRD §10 only says "already signed-out session = success"; the expired case is not ruled.
Proposed change (exact):
(1) WorkerManifest task entry gains optional `scope: 'tenant' | 'platform'` (default 'tenant'); for 'platform' core runs the handler with
    ctx.tenantId = undefined under system claims and skips `tenantOf`. Plus two SECURITY DEFINER functions owned by C0-0B for the worker role:
    platform invitation load/mark (issued_at / failed) and platform mfa_factors removal (removal_reason, removed_by), mirroring the A38-1 pair.
(2) Decision needed, one of: (a) refresh-then-signOut: worker refreshes with the stored refresh token, then signOut(new token,'local');
    (b) treat 403 bad_jwt as "gone" = success, and the LIMS session row revocation (already committed by the API) is the only guarantee;
    (c) fall back to adminSignOutUser(user_id) (signs out ALL the user's sessions — conflicts with "other sessions survive").
    C2 recommends (a).
Backward compatible? yes — `scope` defaults to 'tenant'; existing manifests unchanged.
Tenant/security impact: no RLS change on tenant tables; new DEFINERs touch only tenant_id IS NULL rows and must be REVOKEd from PUBLIC and
granted to the worker role only (07-SECURITY DEFINER inventory). (2a) keeps refresh tokens in worker memory only for one call.
IRD/regulatory impact: none.
Alternatives considered: payload carries a sentinel tenant_id (rejected: platform rows have NULL tenant, RLS would hide them);
C2 enqueues platform jobs from the API with direct GoTrue calls instead (rejected: loses retry/dead letter, 02-TRD §10).
Tests that will prove it: worker core test: platform-scope task runs with tenantId undefined, payload without tenant_id accepted;
C2.T11 tests: platform sign-out / invite / MFA-reset with real repos reach GoTrue fake; expired token case per the chosen option.
