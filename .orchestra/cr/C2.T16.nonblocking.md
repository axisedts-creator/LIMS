Title: CR-C2-T16: columns for LD-26 tenant.training_mode and LD-27 signatory council
From chunk: C2            To owner: C2 (05-SCHEMA / identity migrations, contracts/openapi/identity.yaml, IdentityPort TenantSettings)
Type: schema
Blocking? no for T16 tests; yes for LD-26 consumers (C4/C6/C15) and the LD-27 report footer.
Problem: LD-26 needs a provisioning-only, immutable `training_mode` setting readable through the C2 settings read port; identity.tenant_settings has no such column and TenantSettings (IdentityPort) has no key. LD-27 needs `council` ('NMC'|'NHPC') + `registration_no` (<=20) on the signatory profile; core.memberships has only signatory_registration_no (<=40) and no council column.
Proposed change (exact): (1) `ALTER TABLE identity.tenant_settings ADD COLUMN training_mode boolean NOT NULL DEFAULT false` + trigger refusing UPDATE of training_mode (set only by provisionTenant); TenantSettings key `trainingMode` in IdentityPort getTenantSettings; not in TenantSettingsPatch. (2) `ALTER TABLE core.memberships ADD COLUMN signatory_council text CHECK (signatory_council IN ('NMC','NHPC'))`, tighten `signatory_registration_no` to <= 20 when council is set; expose both on the signatory profile DTO / readSignatory port.
Backward compatible? yes (additive, defaults false / NULL).
Tenant/security impact: no RLS change; training_mode immutability enforced in DB (no tenant/platform PATCH path).
Alternatives considered: storing training_mode as a feature flag (rejected: flags are toggleable; LD-26 says immutable).
Tests that will prove it: migration test UPDATE training_mode -> error; updateSettings with training_mode -> 400; port getTenantSettings(['trainingMode']) returns the provisioned value; footer test "<council> No. <registration_no>".
