Title: CR-C2-T17: tenant-claims access for the tenant side of support sessions (SP10 unbind, platform staff display name)
From chunk: C2            To owner: C2 (05-SCHEMA §5 identity RLS / definers, db/policies/identity.sql)
Type: schema (RLS / SECURITY DEFINER)
Blocking? no for T17 unit tests; yes for real SP10 cut-off and a correct SupportSession.platform_staff_display_name on tenant reads.
Problem: (1) revokeSupportSession must clear identity.sessions.support_session_id of the bound platform session (SP10). Platform session rows have tenant_id NULL; sessions__update__tenant requires tenant_id = current tenant, so the UPDATE under tenant claims matches 0 rows (silent no-op). (2) listTenantSupportSessions / approve / deny / revoke return SupportSession.platform_staff_display_name (required) but no lims_app policy lets tenant claims SELECT identity.platform_staff; the repo LEFT JOINs and returns '' until fixed.
Proposed change (exact): (1) SECURITY DEFINER `app.identity_unbind_support_session(p_tenant_id uuid, p_support_session_id uuid)` that updates identity.sessions SET support_session_id = NULL WHERE kind = 'platform' AND support_session_id = p_support_session_id AND EXISTS (support_sessions row with tenant_id = p_tenant_id = app.current_tenant_id()); GRANT EXECUTE to lims_app; definer-inventory entry. Alternative: T8 resolver rejects a platform session whose bound support session is not `active` (then no unbind needed). (2) Either a definer/view exposing (id, display_name) of platform staff referenced by the tenant's support_sessions, or denormalise platform_staff_display_name onto identity.support_sessions at open time.
Backward compatible? yes (additive).
Tenant/security impact: definer must assert p_tenant_id = app.current_tenant_id() and is_staff_or_system(); exposes only the display name, never email/user_id.
Tests that will prove it: DB test: tenant claims call the definer -> platform session unbound; tenant B id -> 0 rows. Tenant read of support sessions returns the staff display name.
