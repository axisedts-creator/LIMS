Title: CR-C2-T25: add the missing lims_app `__platform` policies on identity.platform_staff, identity.platform_events, identity.auth_events
From chunk: C2            To owner: C2 (05-SCHEMA §10.1 / identity migration; db/ change needs CR ref per 04 §3.5)
Type: schema
Blocking? no for T25 unit/handler tests (fake repo); yes for live T25 endpoints and the plan's T25 "integration" test (06 row T25: listPlatformStaff, invitePlatformStaff, updatePlatformStaff, deactivatePlatformStaff, resetPlatformStaffMfa, listPlatformAuthEvents).
Problem: C2 05-SCHEMA §5.3 (table, lines 415/417/418) requires `__platform` policies TO lims_app for identity.platform_staff (SELECT, INSERT, UPDATE), identity.platform_events (SELECT, INSERT) and identity.auth_events (SELECT). 05-SCHEMA §10.1 DDL and db/migrations/20261105001300_identity__create_identity_schema.sql create only the `__owner_only` policies (TO lims_owner) on these tables; `__platform` exists for sessions, mfa_factors, invitations, tenant_settings only. Under FORCE RLS every T25 repo query (repository/platform-staff.repo.ts) run as lims_app under platform claims is denied (0 rows on SELECT, error on INSERT/UPDATE). §5.3 and §10.1 are inconsistent. Serves US-E6 (T25 done_when: IP allowlist enforced; last superadmin protected).
Proposed change (exact), appended to 05-SCHEMA §10.1 and a new identity migration:
  CREATE POLICY platform_staff__select__platform ON identity.platform_staff FOR SELECT TO lims_app USING ((SELECT app.is_platform_actor()));
  CREATE POLICY platform_staff__insert__platform ON identity.platform_staff FOR INSERT TO lims_app WITH CHECK ((SELECT app.is_platform_actor()));
  CREATE POLICY platform_staff__update__platform ON identity.platform_staff FOR UPDATE TO lims_app USING ((SELECT app.is_platform_actor())) WITH CHECK ((SELECT app.is_platform_actor()));
  CREATE POLICY platform_events__select__platform ON identity.platform_events FOR SELECT TO lims_app USING ((SELECT app.is_platform_actor()));
  CREATE POLICY platform_events__insert__platform ON identity.platform_events FOR INSERT TO lims_app WITH CHECK ((SELECT app.is_platform_actor()));
  CREATE POLICY auth_events__select__platform ON identity.auth_events FOR SELECT TO lims_app USING ((SELECT app.is_platform_actor()));
  (plus the matching GRANT SELECT/INSERT/UPDATE to lims_app if §10.1 grants are missing for these pairs.)
Backward compatible? yes (additive policies; no column / contract change).
Tenant/security impact: RLS change (REQ-SEC-042, REQ-SEC-063). Grants platform actors (aal2, active staff row; app.is_platform_actor contract §5.1/§358) exactly the access §5.3 already specifies; no tenant actor gains anything (is_platform_actor() false under tenant claims). auth_events: SELECT only, INSERT stays via app.identity_record_auth_event. No PHI, no new public surface. Needs 05-DoD §4 security sign-off (04 §3.6).
Alternatives considered: DEFINER functions per T25 operation (rejected: contradicts §5.3 and A28.1 "after login, platform-context operations write under __platform"); granting via owner policies (rejected: owner policies are for §6 DEFINERs only, §5.4).
Tests that will prove it: 05-SCHEMA §11 policy-inventory test lists the six policies with role lims_app and predicate app.is_platform_actor(); RLS tests: under platform claims (aal2, active staff) SELECT/INSERT/UPDATE succeed; under tenant claims and under platform claims with aal1 or inactive staff they return 0 rows / are rejected; auth_events INSERT as lims_app rejected. Then the T25 integration test against the real DB.
