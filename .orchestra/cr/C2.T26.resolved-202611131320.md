Title: CR-C2-T26: platform console reads/routes missing for PL-2..PL-8
From chunk: C2            To owner: C2 (contracts/openapi/identity.yaml, contracts/routes.yaml) + C0-0D (nav build)
Type: api
Blocking? partly — T26 Feature-flags tab (PL-3) depends on an assumed read; other items are UI gaps, worked around.
Problem:
1. No platform read of a tenant's feature flags (only tenant-context listFeatureFlags). PL-3 "Feature flags" tab cannot list flags. T26 calls ASSUMED `GET /v1/identity/platform/tenants/{tenant_id}/feature-flags` → FeatureFlagList (actions.listTenantFlagsAction).
2. No list of an IRD annex record's documents → PL-4 documents list, download and "Scan pending" (P-19) not built; upload only.
3. listTenants rows have no users/centres/annex_readiness → PL-2 columns Users, Centres, IRD readiness show "—".
4. PlatformStaff has no MFA field → PL-7 MFA column shows "—" (UI reads optional `mfa_enrolled` if added).
5. listPlatformAuthEvents has no "no tenant" filter → PL-8 "No tenant" filters the loaded page client-side.
6. routes.yaml has only staff.platform.tenant / staff.platform.dead_letter. Nav manifest uses routeIds staff.platform.{home,tenants,ird,support_sessions,dead_letters,staff,auth_events} (not in routes.yaml; build:nav will reject them).
Proposed change (exact):
1. identity.yaml: `GET /v1/identity/platform/tenants/{tenant_id}/feature-flags` operationId listFeatureFlagsAsPlatform, x-permission platform.tenant.read, x-context platform, 200 FeatureFlagList.
2. identity.yaml: `GET /v1/identity/platform/ird-annexes/{record_id}/documents` → { data: IrdAnnexDocument[] }, platform.tenant.read.
3. TenantPage rows: optional `counts {users, centres}` and `annex_readiness` (as TenantDetail).
4. PlatformStaff: optional `mfa_enrolled: boolean`.
5. listPlatformAuthEvents: `tenant_scope` query enum [tenant, none] (or `platform_rows=true` like listDeadLetters).
6. routes.yaml: add the seven staff_web routes (paths/permissions from C2 04-UI-UX §1: /platform, /platform/tenants, /platform/ird, /platform/support-sessions, /platform/dead-letters, /platform/staff, /platform/auth-events).
Backward compatible? yes (additive).
Tenant/security impact: platform-only reads under platform context; no new PHI; no tenant surface.
Alternatives considered: hide the tabs/columns (loses PL-3/PL-2 spec content).
Tests that will prove it: t26.tenants "PL-3 Feature flags tab", t26.source nav manifest + build:nav.
