Title: CR-C2-T28-002: DB samplers for the identity gauges of 02-TRD §13 + metrics on the module/job context
From chunk: C2            To owner: C0-0D (worker/API core) ; C0-0B (DEFINER inventory)
Type: schema | port
Blocking? no (T28 tests pass; alert inputs below are partial until this lands)
Problem: 02-TRD §13 says lims_identity_active_sessions{kind} and lims_identity_support_sessions_active are "sampled every 5 min", and the
backing gauges lims_identity_login_failures_by_tenant_5m{tenant_id}, lims_identity_stuffing_distinct_accounts_15m / _ips_15m are
"sampled every minute from identity.auth_events". These are cross-tenant counts: lims_app / lims_worker see one tenant at a time (RLS,
05-SCHEMA §5), tenantless auth_events rows are unreachable, and 05-SCHEMA §6 inventories no DEFINER for them. No task id / schedule
exists either. Also: (a) handler ctx and worker JobContext carry no `metrics` (core/module.ts HandlerContext, worker core/manifest.ts);
CoreDeps.metrics (core/pipeline/boot.ts) has no observe and no gauge labels, so histograms and labelled gauges are dropped in the API;
(b) IdentityBreachedListMissing (`lims_identity_breached_list_loaded{env="production"} == 0`) fires for every process that registers
the gauge but never sets it (unlabelled prom-client gauge renders 0), i.e. every API/worker process after a restart.
Proposed change: (1) one platform DEFINER returning the sampled counts (active sessions by kind, active support sessions, failed logins of
known accounts per tenant in 5 min via email_hmac -> tenant, distinct failing email_hmac / client_ip in 15 min, breached list present)
+ a worker cron entry calling it every minute and setting the gauges via idMetrics.sampled / tenantFailures5m / stuffing /
breachedListLoaded (services/api/src/modules/identity/metrics.ts); (2) pass CoreMetrics (inc/set/observe with labels) as ctx.metrics to
handlers and jobs, or as CoreDeps.metrics.
Backward compatible? yes (additive).
Tenant/security impact: DEFINER returns counts only, no ids / e-mail / IP (REQ-SEC-133, 02-CV §9.2).
Alternatives considered: process-local windows (in place now for login throttles / stuffing / tenant failures [CONV]: per instance,
wrong-password failures carry no tenant); dropping the gauges (breaks the TRD alert rules).
Tests that will prove it: identity observability.test.ts (already); a sampler test asserting each gauge from seeded rows; a boot test
asserting ctx.metrics reaches a handler.
