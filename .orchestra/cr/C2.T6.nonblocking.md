Title: CR-C2-T6: C0 limiter has no `f:` rule / failure-window primitives; SessionState.actor has no source at login
From chunk: C2            To owner: C0-0D (core/ratelimit), C2 (05-SCHEMA app.identity_login_context / contracts/openapi/identity.yaml)
Type: shared-lib | api
Blocking? no for T6 tests (109/109 pass); yes for multi-instance production correctness of the 08 A1 throttle and for a contract-valid 200 body.
Problem:
(1) 02-TRD §4 item 11 / 03-APP-FLOW §3.3 need, in the shared C0 store: a per-account failure window (sliding 60 min, read without consuming: count + last failure time, clear on success/reset/unlock) and a per-IP `f:<client_ip>` failure counter (10/10 min engages 5 attempts/min for 30 min). core/ratelimit/index.ts RULES has only `login: { 'a:' }` and `consume()` is the only verb (its comment says `f:` is "applied by C2"). T6 therefore keeps these windows process-local in handlers/loginStaff.ts (createAuthLimits): N API instances = N x thresholds; restart forgets them. AC-A1.5/A1.6/A1.6a-b, AU-T2b.
(2) OpenAPI SessionState requires `actor { display_name, roles }`; app.identity_login_context returns neither display name nor role codes. loginStaff omits `actor` rather than invent it, so the 200 body does not yet satisfy SessionState if responses are validated.
Proposed change (exact):
(1) C0 RateLimiter gains `failures(tier, key): Promise<{ count: number; last: Date | null }>`, `recordFailure(tier, key)`, `clearFailures(tier, key)` and a `login` rule `'f:'` with the 08 A1 thresholds (throttle state + 5/min check), all HMAC-keyed like consume(). C2 then swaps the Maps in createAuthLimits for these calls (AuthLimits seam unchanged).
(2) Either add `display_name text, role_codes text[], tenant_code text` to the app.identity_login_context RETURNS TABLE, or make SessionState.actor optional on LoginResult (filled by resolveSession).
Backward compatible? yes (additive).
Tenant/security impact: no RLS change; (1) closes the per-instance bypass of the brute-force limits (REQ-SEC-078/079).
Alternatives considered: an UNLOGGED C2 table for the counters (rejected: 03-APP-FLOW §3.3 puts state in the C0 rate-limit store).
Tests that will prove it: auth.service.test.ts AuthLimits contract run against the C0 adapter with two limiter instances sharing one backend; contract test of the loginStaff 200 body against SessionState.
