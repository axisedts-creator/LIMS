Title: CR-C3-024: worker core — per-task REPEATABLE READ job transaction + final-failure hook in the dead-letter transaction
From chunk: C3            To owner: C0-0D (services/worker/src/core)
Type: port
Blocking? yes — C3 T-24 (catalog.export_build): 02-TRD §8.7 snapshot and 02-TRD §10 final-attempt `failed` state are not met against real Postgres. Same final-failure gap in T-22 catalog.import_validate.ts:117.
Problem:
  1. 02-TRD §8.7: the export is built from ONE consistent snapshot (REPEATABLE READ). taskRun (core/consumer.ts:103) opens the job tx and runs set_config claims (tenant-scope.ts:6) before the handler; ctx.db.tx = fn(ctx) reuses it (consumer.ts:58). A handler `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ` is then rejected (SQLSTATE 25001). No way to get the snapshot.
  2. 02-TRD §10 l.711/l.718: on the final attempt the export goes `queued`/`building` -> `failed` "in the same transaction as the dead-letter insert". That tx is core capture() (core/deadletter.ts:35), which has no per-task hook; a write in the job tx before a rethrow is rolled back. Interim in T-24: the final attempt writes `failed` on the job tx and resolves (no dead letter); if the error was a Postgres error the tx is aborted (25P02), the UPDATE throws and the export stays `queued`.
Proposed change (exact):
  1. manifest `taskOptions[id].isolation?: 'repeatable_read'`; taskRun opens the job tx with `BEGIN ISOLATION LEVEL REPEATABLE READ` (before set_config) when set. catalog.export_build sets it.
  2. manifest `taskOptions[id].onFinalFailure?: (tx, payload, code: string) => Promise<void>`; capture() calls it inside its dead-letter tx, with the same tenant claims, after the dead-letter insert. catalog.export_build / catalog.import_validate move their `failed` UPDATE there and always rethrow.
Backward compatible? yes — both options optional; tasks without them behave as today.
Tenant/security impact: none on RLS (same claims); no new PHI; no public surface. Hook gets only the error code (07 S-13: no error text).
IRD/regulatory impact: n/a
Alternatives considered: SAVEPOINT around the build (fixes 25P02 but still skips the dead letter, and not the snapshot); a second pool connection from the task (bypasses core claims, rejected).
Tests that will prove it: core unit test (isolation option -> BEGIN ISOLATION LEVEL REPEATABLE READ; hook runs in capture tx); C3 exportBuild.test.ts `it.todo` snapshot test turned into a real test; final-attempt test asserts rethrow + `failed` persisted via the hook.
