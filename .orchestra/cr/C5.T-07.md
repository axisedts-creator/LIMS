Title: CR-C5-T07-001: LD-25 downtime back-entry on specimen writes has no contract fields, setting, audit action or storage
From chunk: C5            To owner: C0-0C (api), C0-0B (schema), C2 (TenantSettings), C0 (audit access actions)
Type: api | schema | port
Blocking? no (T-07 parses/validates LD-25 in the service, audits with a stand-in action, window = constant 72 h; contract/columns/setting wait on this)
Problem: LD-25 (2026-11-07) requires C5 specimen writes to accept `entry_mode`/`occurred_at`/`downtime_ref`, store both, audit it, with window `downtime_backentry_max_hours` (tenant setting, default 72). Today: (1) contracts/openapi/lab.yaml request bodies are additionalProperties:false without the 3 fields (C5 may not edit contracts/); (2) audit.g_cs_access_actions has no specimen/downtime action, so T-07 writes `patient.view` (a false PHI-access entry); (3) TenantSettings has no `downtime_backentry_max_hours`; (4) lab.specimens / lab.specimen_transitions have no `entry_mode`/`downtime_ref` columns (only the audit detail holds them).
Proposed change (exact):
 (1) OpenAPI (lab.yaml): add to the request bodies of collectSpecimen, bulkCollectSpecimens, bulkDispatchSpecimens, receiveSpecimen, bulkReceiveSpecimens, storeSpecimen, discardSpecimen (top level; bulk = applies to every item):
     `entry_mode: {type: string, enum: [live, downtime_backentry], default: live}`, `occurred_at: IsoUtc`, `downtime_ref: {type: string, minLength: 1, maxLength: 32}`.
 (2) Audit: add an access action for specimen downtime back-entry (e.g. `specimen.downtime_backentry`) to audit.g_cs_access_actions.
 (3) TenantSettings.downtime_backentry_max_hours (int, default 72) — shared with CR-C4-FD-T06-001.
 (4) DDL: lab.specimen_transitions (or lab.specimens) `entry_mode text NOT NULL DEFAULT 'live' CHECK (entry_mode IN ('live','downtime_backentry'))`, `downtime_ref text CHECK (char_length(downtime_ref) <= 32)`; occurred_at is already stored as the transition/action time.
Backward compatible? yes (all optional, default live)
Tenant/security impact: none new; removes a misleading `patient.view` audit row.
IRD/regulatory impact: none (no invoices in C5).
Alternatives considered: same stand-ins as FD-T06 (.orchestra/cr/FD-T06-ld25-gaps.md); kept until C0 rules.
Tests that will prove it: handlers/__tests__/specimen.handlers.integration.test.ts LD-25 blocks + contract validation of the 7 bodies + new column/setting/audit-action assertions.
