Title: CR-C5-T20-001: result grid needs patient_id on the order, a worklist source for Alt+N/Alt+P, and LD-25 fields on result history rows
From chunk: C5            To owner: C0-0C
Type: api
Blocking? no (T-20 ships with fallbacks: F3 says "The trend is not available", Alt+N/Alt+P do nothing, history shows no "Entered after downtime" marker)
Problem:
  1. AC-11.2 (trend chart on F3): #getAnalyteTrend is `/v1/lab/patients/{patient_id}/analytes/{analyte_id}/trend`, but lab.yaml OrderResultsResponse.order (LabOrderDto) and ResultDto carry no patient id, so the grid page cannot call it.
  2. 04-UI-UX §3.6 Alt+N / Alt+P (next / previous order in the worklist): #listOrderResults returns one order; no operation gives the grid the neighbouring order ids of the bench worklist.
  3. LD-25 (2026-11-07): history must show "Entered after downtime" with the original time. ResultHistory rows (#getResultHistory) have no `entry_mode` / `occurred_at` (ResultDto lacks them too).
Proposed change (exact):
  1. LabOrderDto (or OrderResultsResponse.order) gains required `patient_id` ($ref _common.yaml Uuid). Same RLS / centre scope as the order read.
  2. OrderResultsResponse gains optional `worklist: { prev_order_id?: Uuid, next_order_id?: Uuid }` computed from the same department/bench filter as the worklist (no patient identifiers, REQ-SEC-098).
  3. ResultHistory row items and ResultDto gain optional `entry_mode` (enum live | downtime_backentry), `occurred_at` (IsoUtc), `downtime_ref` (string, maxLength 32), as stored by T-07/T-14 per LD-25.
Backward compatible? yes (additive; additionalProperties false means clients must be regenerated, no field removed).
Tenant/security impact: patient_id is an opaque uuid already readable via other lab reads with the same permission; it is used only in an API path (P-02), never in a browser URL query. No new public surface.
Alternatives considered: a separate order→patient lookup from C4 (extra round trip and cross-chunk read per page load); client-side worklist from the previous screen's state (lost on reload / deep link).
Tests that will prove it: lab result-entry handler integration (patient_id, worklist neighbours, history entry_mode); c5-t20 grid tests (F3 renders TimeSeriesChart from page data, Alt+N navigates, history shows "Entered after downtime").
