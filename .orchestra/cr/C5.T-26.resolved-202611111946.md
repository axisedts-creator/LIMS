Title: CR-C5-T26-001: WorksheetDto cannot carry the worksheet print content required by 04-UI-UX §3.15 / 03-APP-FLOW §3.6 (created by, reg no, patient, priority, Code 128)
From chunk: C5            To owner: C0-0C (api) + C0-0D (ui-kit, BarcodeSymbol)
Type: api
Blocking? no (T-26 ships the print view with title, department IdText, instrument, created at, #, barcode text, test, blank Result/Remarks; the missing columns are added when this lands)
Problem: AC-07.4 / 04-UI-UX §3.15 print header needs "created by" and the table needs reg no, patient (name, age/sex), priority ★ and a small Code 128 symbol. contracts/openapi/lab.yaml WorksheetDto is additionalProperties:false with header {id,title,centre_id,processing_centre_id?,department_id?,instrument_id?,created_at} and rows {order_test_id,position,barcode?,test_code}; no other operation returns them for a worksheet. The worksheet_items snapshot (05-SCHEMA) already stores registration_no / priority.
Proposed change (exact), additive in lab.yaml:
  WorksheetDto.properties.created_by: $ref _common.yaml#/components/schemas/Uuid   (optional; web renders a name via the identity display port or IdText)
  WorksheetDto.rows.items.properties:
    registration_no: { type: string, maxLength: 40, pattern: "^[A-Z0-9]{1,40}$" }   # as WorklistItemDto; from the snapshot (immutable)
    priority: { $ref: _common.yaml#/components/schemas/Code }                      # as WorklistItemDto; from the snapshot (immutable)
    patient_display: { $ref: "#/components/schemas/PatientDisplay" }  # fetched at render by #22 via FrontdeskPort.getPatientDemographicsBatch('lab_display') (P-06: never stored in the snapshot)
  ui-kit: confirm BarcodeSymbol (Code 128 SVG; see CR-C5-T10-001) is the component for the barcode cell.
Backward compatible? yes (new optional response fields; existing clients ignore them)
Tenant/security impact: patient_display is PHI already returned by #18/#19 under lab.worklist.read; #22 already logs `worksheet.print` (access log). No RLS change, no new endpoint.
IRD/regulatory impact: none
Alternatives considered: web calls #18 per row (rejected: print must be a snapshot, AC-07.4); undeclared fields (forbidden, 04-CHANGE-REQUESTS §1).
Tests that will prove it: worklist.handlers.test.ts (#22 returns the new fields; patient fetched at render, not from the snapshot) and lab-t26.worklists.test.tsx print-view cases for reg no / patient / ★ / Code 128 svg.
