Title: CR-C5-T27-001: StatusBoardRow needs the release kind (and a last-change time) for "Printed (partial)" / "Printed (preliminary)"
From chunk: C5            To owner: C0-0C
Type: api
Blocking? no (T-27 ships the five board statuses; the "(partial)" / "(preliminary)" chip variants and the "last change" column of 04-UI-UX §3.11 stay unshown until this lands)
Problem: PRD AC-18.3 / 03-APP-FLOW §1.5 / 04-UI-UX §3.11 want the board to say "Printed (partial)" or "Printed (preliminary)". lab.yaml StatusBoardRow has only
  board_status (enum collected|in_lab|ready|printed|waiting) and last_released_at, so the report_kind of the latest release (stored as received in lab.report_releases) cannot reach the screen.
  The same row has no change-time field for the "last change" column.
Proposed change (exact): StatusBoardRow (additionalProperties false) gains optional `last_release_kind` (string, maxLength 32, x-extensible: render unknown kinds as plain "Printed")
  and optional `last_changed_at` (IsoUtc). Handler: last_release_kind = report_kind of the release with max(released_at) (ties: highest version_no).
Backward compatible? yes (optional fields).
Tenant/security impact: none (no PHI; report_kind is a short code); same RLS and centre scope as the board.
Alternatives considered: widening the board_status enum with printed_partial / printed_preliminary (breaks the closed filter pattern and every client); a second endpoint (extra round trip per poll).
Tests that will prove it: statusBoard.handlers.integration (row carries last_release_kind for final / partial / preliminary releases) and the lab-t27 board component test (chip text per kind).
