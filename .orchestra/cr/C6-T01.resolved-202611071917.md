Title: CR-C6-T01: core boot.test sample-module cases boot the real modules dir with no module env
From chunk: C6            To owner: C0-0D
Type: bug
Blocking? yes — C6-T01 (full API suite red once modules/reporting/index.ts exists)
Problem: services/api/src/core/__tests__/boot.test.ts "core sample module" (5 cases) call bootstrap() with the default
modulesDir, so every real module is autoloaded. C6-T01 done_when requires "boot fails on bad config": reporting/index.ts
runs loadReportingConfig(process.env) at import (02-TRD §10.1: LIMS_REPORTING_OTP_HMAC_KEY_FILE required, ≥32 B;
ALLOW_REAL_PROVIDERS must be true in production, REQ-SEC-136). Those tests set neither process.env.LIMS_CORE_ENV nor the
key, and the "production with flag=1" case can never pass with a spec-compliant module config. Result:
"config: LIMS_CORE_ENV must be one of dev|ci|staging|production" / "module reporting: index.ts exports no manifest".
Proposed change (exact): in those 5 cases pass `modulesDir: <empty fixture dir>` (as line 53 already does with
'/does-not-exist'); the sample module is mounted by config.loadSampleModule, independent of modulesDir.
Backward compatible? yes (test-only).
Tenant/security impact: none; avoids weakening REQ-SEC-136 / REQ-SEC-128 checks to satisfy a core test.
Alternatives considered: make the HMAC key optional / default LIMS_CORE_ENV outside prod — rejected (fail-open);
lazy config load — rejected (done_when needs boot failure; no module init hook in bootstrap today).
Tests that will prove it: `pnpm --dir services/api exec vitest run src/core/__tests__/boot.test.ts` green with reporting present.
