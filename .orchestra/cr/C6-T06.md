```
Title: CR-C6-023: AssetRef.mimeType should be optional for signature refs (02-TRD §4.3)
From chunk: C6            To owner: C6 (02-TRD §4.3 ReportDocument types)
Type: shared-lib
Blocking? no  (C6-T06 ships mimeType optional, marked [CONV] in domain/document.ts)
Problem (what you cannot do today, with the user story / acceptance criterion it serves):
  02-TRD §4.3 declares AssetRef.mimeType required. Signature refs (AC-03.7, T15) are minted at assembly from
  IdentityPort.Signatory (03-IC §4.6), which carries signatureAssetId + signatureSha256 but no mime type.
  The mime type is only known from SignatureImageContent.mimeType when the render worker fetches the bytes.
  Assembly cannot fill a required mimeType without an extra image read that P3/T15 keep out of assembly.
Proposed change (exact): TS signature diff in 02-TRD §4.3
  - mimeType: 'image/png' | 'image/jpeg' | 'application/pdf'
  + mimeType?: 'image/png' | 'image/jpeg' | 'application/pdf'   // absent on 'signature' refs; render worker resolves it
  Alternative minimal form: add mimeType to IdentityPort.Signatory (03-IC §4.6) instead.
Backward compatible? yes for producers; renderer (C6-T07) must not assume presence for source = 'signature'.
Tenant/security impact: none (no RLS, no PHI, no new surface).
IRD/regulatory impact: none.
Alternatives considered: read signature bytes during assembly (rejected: extra I/O, T15 keeps image reads in renderer);
  guess image/png (rejected: wrong for JPEG signatures).
Tests that will prove it: document.test.ts signatory cases (signatureAssetRef without mimeType); renderer test with JPEG signature.
```
