From chunk: C6            To owner: C0 (dependency pin) / C6 (02-TRD §6.5 key names)
Type: shared-lib
Blocking? no  (C6-T07 ships an in-tree pure-TS QR encoder and [CONV] key names; both swappable)
Problem (what you cannot do today, with the user story / acceptance criterion it serves):
  1. 02-TRD §1/§15 say the QR encoder (MIT/Apache, pure JS, no network) is pinned by C0; no package or version is pinned
     anywhere (pnpm-lock.yaml, CV). The QR on every report (04-UI-UX §3.2, AC-03.x verify flow) needs an encoder now.
  2. 02-TRD §6.5 `header_fields [ordered subset of the 11 header fields]` names no keys; the schema needs an enum.
  3. 04-UI-UX §3.2 Amended/Addendum box "replaces version {n} issued {date}" needs the issue date of version n;
     02-TRD §4.3 `amendmentNotes[]` has no such field, so the renderer prints amendedAt (a wrong date on a clinical report).
  4. 04-UI-UX §3.2 "PARTIAL REPORT — results for {k} test(s) are still pending." needs {k}; ReportDocument (02-TRD §4.3)
     has no pending-test count, so reportKind 'partial' renders with no box.
Proposed change (exact):
  1. C0 pins a QR encoder package + exact version for services/renderer, or approves the in-tree encoder
     services/renderer/src/templates/lab/qr.ts (byte mode, ECC M, versions 1–10) as the pinned encoder.
  2. 02-TRD §6.5 adds: header_fields keys = sample_collected_at, name, reg_no, age_gender, barcode_no, sample_coll_dt,
     reg_date, sample_rcv_dt, reported_date, report_status, referred_by (labels per 04-UI-UX §3.1).
  3. 02-TRD §4.3 `amendmentNotes[]` adds `previousIssuedAt: IsoUtc`, filled at assembly from `released_at` of version n;
     statusBox (services/renderer/src/templates/lab/shared.ts) then prints previousIssuedAt.
  4. 02-TRD §4.3 ReportDocument adds `pendingTestCount: number`, present when reportKind = 'partial'; statusBox renders
     the §3.2 Partial box from it.
Backward compatible? yes (no stored configs yet).
Tenant/security impact: none (encoder is pure; schema stays closed).
IRD/regulatory impact: none.
Alternatives considered: add a QR npm package with a self-chosen version (rejected: "never invent a version/vendor").
Tests that will prove it: renderer lab-report QR tests; a decode round-trip test once a decoder is available (not in repo today).
