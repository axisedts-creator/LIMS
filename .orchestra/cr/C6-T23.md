Title: CR-C6-027: five send_delivery failure_code values missing from 02-TRD §5.4 / 04-UI-UX §2.5
From chunk: C6            To owner: C6 (doc owner: founder)
Type: api
Blocking? no  (C6-T23 ships them marked [CONV])
Problem (what you cannot do today, with the user story / acceptance criterion it serves):
reporting.send_delivery (AC-09.5 recording-only outside prod, REQ-SEC-136; AC-09.1) must end a delivery `failed` for permanent, non-provider causes. 02-TRD §5.4 (l.534) lists only provider codes (`provider_rejected`, `invalid_destination`, `template_not_approved`) and 04-UI-UX §2.5 has no shown text for the causes below, so the delivery log drawer cannot explain them.
Proposed change (exact): add to 02-TRD §5.4 failure mapping and to the 04-UI-UX §2.5 `failure_code | Shown text` table:
| `channel_not_configured` | "Not sent: no messaging account is set up for this channel." |   (production, no active channel account)
| `provider_not_permitted` | "Not sent: this messaging provider is not allowed here." |       (production + `recording` provider, or real providers not enabled)
| `provider_unavailable` | "Not sent: the messaging provider is not available." |            (no transport adapter for the account's provider_kind)
| `template_text_missing` | "Not sent: no message text is set up for this language." |       (no tenant template text for template_code/channel/language)
| `link_unavailable` | "Not sent: the report link could not be created." |               (deferred link without report/centre)
Backward compatible? yes — additive values of a free-text failure_code column; no CHECK constraint changes.
Tenant/security impact: none; no RLS change, no PHI, no new surface. Texts reveal no message content (REQ-SEC-070).
IRD/regulatory impact (billing changes only): n/a
Alternatives considered: map all five to `provider_rejected` (misleading: the provider was never called) or `retries_exhausted` (wrong: not retried).
Tests that will prove it: services/worker/src/jobs/reporting/__tests__/send_delivery.test.ts (prod without account / recording in prod / missing text cases); a UI test of the §2.5 drawer table once C6 delivery-log UI lands.
