Title: CR-C6-0xx: add latest_version_id to ReportSummary (reporting.yaml)
From chunk: C6            To owner: C6 (contract owner) / C0-0B if the OpenAPI is frozen
Type: api
Blocking? no (C6-T31 works around it: bulk release falls back to the report id)
Problem: Worklist bulk release (04-UI-UX §2.1, R7 `POST /report-versions/bulk-release`) takes report-VERSION ids, but `ReportSummary` (R1 listReports) has no latest version id (`grep latest_version_id contracts/openapi/reporting.yaml` = none). The UI cannot send correct ids; with the fallback the API would reject or release the wrong target.
Proposed change (exact): add optional `latest_version_id: Uuid` (id of the newest non-discarded version) to `ReportSummary`. Staff UI already reads `ReportSummary.latest_version_id` (features/reporting/server/types.ts).
Backward compatible? yes (new optional response field).
Tenant/security impact: none (same tenant/centre scope as the row; no PHI).
Alternatives considered: one detail GET per selected row (N+1, slow); accept report ids in bulk-release (changes R7 semantics).
Tests that will prove it: contract test for listReports includes latest_version_id for reports with a version; C6-T31 bulk-release posts version ids.
