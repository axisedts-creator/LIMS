Title: CR-C6-T33: apply reporting module log denylist (REPORTING_LOG_DENY) in the API and worker core loggers
From chunk: C6            To owner: C0-0D (services/api/src/core, services/worker/src/core) + C0-0A (packages/shared-ts/src/logger)
Type: shared-lib
Blocking? no (C6-T33 ships `createReportingLogger` + log-scan test; the runtime loggers do not yet apply the module keys)
Problem (what you cannot do today, with the user story / acceptance criterion it serves):
02-TRD §12 "Logs" (C6) lists module keys that must never be logged (otp, code, link_url, url, token, destination, body_text, params, to, action_url, action_json, portalUrl; REQ-SEC-098, 02-CV §9.2). C6 exports them as `REPORTING_LOG_DENY` in services/api/src/modules/reporting/observability.ts, but the request logger (services/api/src/core/observability/logging.ts) and the worker job logger (services/worker/src/core/bootstrap.ts) are built with plain `createLogger`, which only applies the shared CV §9.2 substring denylist. C6 cannot edit `core/` or `packages/*` (01-CHUNK-MAP §3).
Proposed change (exact):
1. shared-ts logger: `LoggerOptions.extraDeny?: readonly string[]` — exact, case-insensitive key match, applied recursively alongside the §9.2 denylist (also to `child()` context).
2. api core logging.ts and worker core bootstrap.ts: pass the union of registered module denylists (C6: `REPORTING_LOG_DENY`) as `extraDeny`; or, if per-module scoping is preferred, wrap `ctx.log` for module `reporting` handlers/tasks with the same keys.
3. Worker: log calls currently pass fields as the first argument (`warn({...})`); core should also redact a first-argument object, or C6 moves to `(msg, fields)` once the core path is confirmed.
Backward compatible? yes — additive option; default empty list.
Tenant/security impact: reduces PHI/secret leakage risk in logs (REQ-SEC-098). No RLS change, no new surface.
IRD/regulatory impact (billing changes only): n/a
Alternatives considered: wrapping `ctx.log` inside every C6 handler/task (rejected for now: ~30 entry points, easy to miss one; core-level is one place).
Tests that will prove it: C6 log-scan test (reporting observability test) extended to log through the real api/worker logger with planted PHI under each REPORTING_LOG_DENY key and assert `[REDACTED]`.
