Title: CR-C7-018: optional demographic fields on HostQueryAnswer so the Truth-H80E DSR can carry demographics
From chunk: C7            To owner: C7 (03-INTERFACE-CATALOG `HostQueryAnswer`, drivers/types.ts) via lead
Type: port
Blocking? no. H80-T03 ships with DSP-1/2/3/4/13 empty (interim, cited in drivers/truth_h80e/hostQuery.ts). The 08-ADDENDUM §5 / H80-T03 done_when "DSR carries demographics" is only partly met (DSP-5 sex, DSP-21 barcode, DSP-22 detection mode).
Problem (what you cannot do today, with the user story / acceptance criterion it serves):
`HostQueryAnswer` (03-IC; `services/api/src/modules/instruments/drivers/types.ts`) holds only barcode, status, priority, sex, ageDays and tests. The Truth-H80E DSR (08-ADDENDUM-TRUTH-H80E §5) has DSP-1 patient id, DSP-2 department, DSP-3 name, DSP-4 date of birth and DSP-13 accession number. The driver cannot fill them. The `name_script` option (`as_registered` | `latin_if_available`) cannot take effect without a Latin name form.
Also: the instrument's `protocol_options.hl7v2.ack_sending_app` / `ack_sending_facility` are not reachable through `DriverContext`, so the driver can only use the §6 defaults `LIS` / `LIMS` in MSH-3/MSH-4 of the QCK and DSR.
Proposed change (exact): TS signature diff in 03-IC and drivers/types.ts:
  export interface HostQueryAnswer {
    ...existing fields...
+   readonly patientId?: string;        // DSP-1, MRN as registered, ≤ 40
+   readonly department?: string;       // DSP-2, ≤ 64
+   readonly patientName?: string;      // DSP-3, as registered
+   readonly patientNameLatin?: string; // DSP-3 when name_script = latin_if_available and present; else patientName
+   readonly dateOfBirth?: string;      // DSP-4 'YYYYMMDD', only when recorded; never derived from ageDays
+   readonly accessionNumber?: string;  // DSP-13
  }
Optionally `DriverContext.ackSendingApp?` / `ackSendingFacility?` (string, from protocol_options.hl7v2) so MSH-3/MSH-4 follow the instrument config; absent = `LIS` / `LIMS`.
Backward compatible? yes. All fields optional; existing drivers ignore them; the host-query service fills them only for answers with status `found`.
Tenant/security impact: new PHI fields travel from the API to the bridge agent (already PHI-bearing channel, REQ-SEC per 07-SECURITY host query section). No RLS change, no new public surface. Fields go only into the reply bytes, never into logs or error reasons. DSP-6 (patient phone/address) stays empty (PHI minimisation).
IRD/regulatory impact: none.
Alternatives considered: (a) leave DSP-1..4/13 empty permanently: the analyser prints no patient identity, so tube/report mix-ups cannot be caught at the instrument; (b) put demographics in ctx.options: wrong layer, options are per-instrument not per-sample.
Tests that will prove it: hostQuery.truth_h80e.test.ts golden qry-found.dsr.hl7 extended with DSP-1/2/3/4/13; a case with name_script = latin_if_available with and without patientNameLatin; a case where dateOfBirth is absent and ageDays present => DSP-4 empty; escaping of `|^~\&` in name/department.
