Title: CR-C7-023: `SessionProfile` field `HL7AckFullForm` (bool, default false) for the Getein Metis ACK
From chunk: C7            To owner: C7 (agent)
Type: agent spec
Blocking? no (MET-T01 code + tests are done and green; only the CR id citation in code comments waits on approval). CR-C7-021/022 are reserved by 09-ADDENDUM-GETEIN-METIS §8, so this takes 023.
Problem: 09-ADDENDUM-GETEIN-METIS §6 requires the ACK to an ORU to be `ACK^<trigger>`, echo MSH-10 (also in MSA-2), MSH-12 and MSH-16, and carry MSH-18 `UTF8` with MSA text + error code on failure. Today's agent ACK (02-TRD §5.5) is the short form used by every existing profile incl. truth_h80e. §7's profile literal has no field to select the §6 form, and 02-TRD §5.5 `SessionProfile` (02-TRD.md:304) has none either. MET-T01 added `HL7AckFullForm` without a CR (review MET-T01-review.md item 1); precedent CR-C7-016 (08-ADDENDUM:231) says new `SessionProfile` fields go through an agent-spec CR.
Proposed change (exact): add to `SessionProfile` in 02-TRD §5.5: `HL7AckFullForm bool // default false = today's short ACK; true = 09-ADDENDUM-GETEIN-METIS §6 ACK (ACK^<trigger>, MSH-10/MSA-2 = original id, MSH-12/16 echoed, MSH-18 UTF8, MSA text + error code)`. Add `HL7AckFullForm: true` to the getein_metis literal in 09-ADDENDUM §7. Implemented in apps/bridge-agent/internal/drivers/profile.go, registry.go, hl7/ack.go (`AckOptions.FullForm`), mllp/session.go (`Config.AckFullForm`).
Backward compatible? yes. Zero value keeps today's ACK; only getein_metis sets it. truth_h80e and all other profiles unchanged (their tests pass unmodified).
Tenant/security impact: none. No RLS, no PHI field, no new public surface. ACK carries only message-control ids and version/ack-type fields echoed from the analyser's own message.
Alternatives considered: (a) key the full form off the profile code `getein_metis`: rejected, hard-codes a driver name in the MLLP layer. (b) always send the full form: rejected, changes behaviour for truth_h80e and other profiles (LD-163, task brief "no existing profile changes behaviour"). (c) overload `HL7AckMode`: rejected, that field already means original/enhanced mode, not message shape.
Tests that will prove it: drivers/getein_metis_test.go (profile literal incl. HL7AckFullForm=true; every other profile false); mllp/getein_metis_test.go (full-form bytes match §6 incl. trailing pipes; TestMetis_WithoutFullFormTheAckIsTodaysShortForm); simulator sessions testdata/sessions/metis-*.session.json (ORU patient/QC/calibration ACK echoes MSH-10/12/16 + MSH-18 UTF8).
