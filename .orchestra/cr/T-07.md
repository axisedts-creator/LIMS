Title: CR-C1-T07: render PgBouncer auth_file `/run/lims/secrets/pgbouncer/userlist.txt`
From chunk: C1            To owner: C1 (lead) / owner of role `secrets_render` + `infra/secrets/schema/*` (T-06)
Type: gap
Blocking? yes - T-07 done_when "lims_api authenticates" on a real deploy (data-1 / lean prod-1, LD-45). Static T-07 tests pass.
Problem: `infra/compose/supabase/override.data.yml` (T-07, 02-TRD s7.6) bind-mounts `/run/lims/secrets/pgbouncer/userlist.txt` read-only onto `/etc/pgbouncer/userlist.txt` (auth_file for `auth_user = pgbouncer`; lims_api resolves via `auth_query`). Nothing renders that file: `secrets_render_placement` (`infra/ansible/roles/secrets_render/defaults/main.yml`) and `infra/secrets/schema/*.secrets.schema.yaml` deliver `POSTGRES_PASSWORD` to data-1 only as env (`supabase.env`). With short-syntax bind mounts Docker creates a missing source as a directory, so the pgbouncer container fails to start (directory mounted onto a file path).
Proposed change (exact): in `secrets_render`, render on hosts in group `data` (lean: prod-1) the file `{{ secrets_render_secrets_dir }}/pgbouncer/userlist.txt`, mode 0400, owner = pgbouncer container UID (add to `secrets_render_uids`), content one line: `"pgbouncer" "<POSTGRES_PASSWORD plaintext>"`. Plaintext is required: auth_user logs in to the server itself, a SCRAM verifier is not enough. Derived from the existing `POSTGRES_PASSWORD` secret id (no new secret id, no new rotation); rotation of POSTGRES_PASSWORD must re-render this file and reload pgbouncer.
Backward compatible? yes (additive file on tmpfs).
Tenant/security impact: no RLS / PHI / public surface change. File lives on tmpfs only (02-TRD s8.3), 0400, never in git; same secret already present on the host as env.
Alternatives considered: drop the mount and let the pinned edoburu entrypoint write `"$DB_USER" "$DB_PASSWORD"` from env - needs test changes (AuthTest.test_auth_file_mounted_from_secrets_tmpfs, test_t07_live.py) and is unverified for the pinned digest; not the writer's call.
Tests that will prove it: secrets_render test asserting the file is rendered 0400 on data hosts with the two quoted fields; `test_t07_live.py` (LIMS_T07_LIVE=1) with the rendered file mounted: pgbouncer starts, `SHOW CONFIG` pool_mode=transaction / max_prepared_statements=200, lims_api login via auth_query succeeds.
