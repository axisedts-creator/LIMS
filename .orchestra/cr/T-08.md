Title: CR-C1-T08: name the seed runner command and its argument form
From chunk: C1            To owner: C0-0B (owner of `pnpm db:migrate` / `db/seeds/*`)
Type: shared-lib
Blocking? no - T-08 static tests pass with a placeholder; the real deploy (AC-27.2 "migrations + registry-sync + seeds in order on dev") cannot run seeds until the name is fixed.
Problem: `infra/ansible/playbooks/deploy.yml` (T-08, 02-TRD s7.9 step 3) runs seeds in the `migrate` container after `pnpm db:migrate` and `pnpm worker:registry-sync`. C0 03-APP-FLOW s1.4 (line 74) says "seeds 001-003 (prod) / all seeds (dev, ci, staging)", and C0 04-UI-UX s412-415 name `pnpm db:migrate` and `pnpm worker:registry-sync`, but no seed command is named anywhere. The playbook currently uses `pnpm db:seed <files>` (prod: `db/seeds/001_core__g_permissions.sql db/seeds/002_core__g_system_actors.sql db/seeds/003_audit__g_cs_access_actions.sql`) / `pnpm db:seed --all` (staging/dev), marked `UNVERIFIED - pending CR T-08`.
Proposed change (exact): C0-0B adds to the C0 04-UI-UX commands table a seed command, e.g. `pnpm db:seed` with (a) a production form that applies only seeds 001-003 and (b) a form that applies all seeds; document the argument form (file paths, `--all`, or selection by `LIMS_CORE_ENV`), connection inputs (libpq `PGHOST/PGPORT/PGUSER/PGDATABASE` + `PGPASSWORD`, or another), and idempotency (safe re-run on every deploy).
Backward compatible? yes (additive command).
Tenant/security impact: none; runs as `lims_migrator` from the app host only (pg_hba), no new surface.
Alternatives considered: run seeds via `psql -f` in the container - bypasses C0's runner and its checks; not C1's call. Fold seeds into `pnpm db:migrate` - needs a C0 decision.
Tests that will prove it: `infra/tests/static/test_t08_db_flow.py` (seed step after registry-sync, prod 001-003 only) updated to the named command; `infra/tests/integration/test_t08_live.py` (LIMS_T08_LIVE=1) on dev.
