Title: CR-C1-T10: restore drill gaps - repo2 SFTP key consumer + C0 billing export CLI
From chunk: C1            To owner: C0 (export-tenant-billing.ts CLI); C1/secrets schema owner (repo2_sftp_private_key consumers)
Type: shared-lib | bug
Blocking? no  (T-10 ships; billing dry run reports SKIP until (b) lands)

Problem:
(a) infra/secrets/schema/*.secrets.schema.yaml lists consumers of `repo2_sftp_private_key` without the ops-1 restore drill,
    but infra/ansible/playbooks/restore-drill.yml (task "Decrypt repo2 pass and SFTP key on the controller (SOPS)")
    decrypts it to reach repo2 (02-TRD s9.6 step 1, AC-13.1). The consumer list is therefore incomplete.
(b) 02-TRD s9.6 step 3 requires a billing export dry run via C0 `export-tenant-billing.ts` (04 D16). C0 has not
    published the CLI (no argv/flags), so `drill_billing_dry_run_argv` is [] and the check is permanently SKIP.

Proposed change (exact):
(a) add "ops-1 restore drill (infra/ansible/playbooks/restore-drill.yml, drill scope, tmpfs only)" to the consumers of
    `repo2_sftp_private_key` (same as `pgbackrest_repo2_cipher_pass` drill scope, AC-12.3).
(b) C0 publishes the export-tenant-billing.ts CLI contract: invocation, dry-run flag, DB connection input, exit codes.
    C1 then sets `drill_billing_dry_run_argv` (no flag names invented here).
Backward compatible? yes (additive)
Tenant/security impact: no RLS change, no new PHI field, no new public surface. Key stays tmpfs-only, no_log (07-SEC control 2, AC-12.3).
IRD/regulatory impact: (b) only verifies an existing export; no billing rule change.
Alternatives considered: separate drill-only SFTP key (more key material, no benefit); dropping the billing check (violates 02-TRD s9.6).
Tests that will prove it: secrets schema test lists the drill consumer; T-10 drill report shows billing_export_dry_run PASS on staging.
