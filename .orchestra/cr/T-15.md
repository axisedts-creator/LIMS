Title: CR-C3-T15: auto code (`DR{seq:5}` / `CP{seq:5}`) must skip codes already taken in the tenant
From chunk: C3            To owner: C3 (lead)
Type: bug
Blocking? no for T-15 tests (267/267 pass). Yes for AC-11.1 robustness once a tenant holds an explicit code in the auto range; also hits T-16 (`CP{seq:5}`, 02-TRD:173) and the T-17/AC-17.6 imports (`doctor_code` blank = auto, 02-TRD:641).
Problem:
Explicit codes are allowed (#62 `doctor_code`, 02-TRD:172; imports upsert by code, 02-TRD:641). If a tenant already has an explicit `DR00003` and `catalog.code_counters.next_value` hands out `DR00003`, `insertRow` hits UNIQUE (tenant_id, doctor_code) and returns `409 catalog.code_duplicate`. The transaction rolls back, so `next_value` never advances, and EVERY later quick-add (AC-11.1, front-desk flow) fails with the same 409 until someone changes the counter by hand. The spec says neither "skip" nor "fail" (05-SCHEMA:18, :245-253; 02-TRD §5.1).
Proposed change (exact):
Add to 02-TRD §5.1 (Doctor and CreditParty rows): "Auto code: take `next_value` from `code_counters`; if the resulting code already exists in the tenant (any `is_active`, incl. merged), take the next value; give up after 100 tries with `409 catalog.code_duplicate` [CONV]."
Implementation (services/api/src/modules/catalog/service/referrers.service.ts `createDoctor`, same in T-16 credit parties): when `explicit` is undefined, loop `nextCode` while `SELECT 1 FROM catalog.doctors WHERE tenant_id = $1 AND doctor_code = $2` returns a row, max 100 tries. The counter row lock already serialises concurrent quick-adds, so no race between the check and the insert within a tenant.
Backward compatible? yes (only removes a failure; no schema, API or event change).
Tenant/security impact: none. Query stays tenant-scoped (`tenant_id` explicit + RLS); no new field, no new surface.
Alternatives considered: (1) keep 409 - permanently blocks quick-add, rejected. (2) on 409 advance the counter in a separate transaction - two transactions, more code, same result. (3) forbid explicit codes matching `^DR[0-9]{5}$` - breaks imports of existing doctor lists.
Tests that will prove it: integration in `__tests__/integration/referrers.service.test.ts`: seed explicit `DR00001`, `DR00002`; quick-add without code returns `DR00003` and `next_value` = 4; seed 100 consecutive taken codes, quick-add returns `409 catalog.code_duplicate`. Same pair for credit parties in T-16.
