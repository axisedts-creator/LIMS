  But every core tenant table is FORCE RLS and its INSERT policies are `TO lims_app` only; lims_owner is not a member of lims_app and

  001/002/003 load; 010 fails at line 12: `ERROR:  new row violates row-level security policy for table "tenants"`.
Proposed change (exact, recommended):
  db/bootstrap/00_roles.sql: `GRANT lims_app TO lims_migrator WITH INHERIT FALSE, SET TRUE;`
  02-TRD §4.6: tenant-scoped seeds (010+) run `SET LOCAL ROLE lims_app` (after the claims) instead of lims_owner, so the real
  `<table>__insert__tenant` policies' WITH CHECK applies; class-G seeds (001-003) keep `SET LOCAL ROLE lims_owner`.
  (SET ROLE is checked against the session user lims_migrator, so a file can switch owner -> app.) lims_app already has INSERT on all 9 tables.
  Tester's static rule "every seed runs SET LOCAL ROLE lims_owner" would then become "001-003 lims_owner; 010+ lims_app" (T0B-09 test change).
Backward compatible? yes (role grant only; no table/policy change).
Tenant/security impact: lims_migrator can already SET ROLE lims_owner (stronger); gaining SET lims_app adds no privilege and no BYPASSRLS.
  Seeds stay under the real tenant policies (REQ-SEC-040/044 spirit). No new public surface, no PHI.
