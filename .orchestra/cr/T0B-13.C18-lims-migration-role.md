Title: CR-C0-T0B13C18-001: create bootstrap role lims_migration (C18 05-SCHEMA §2) before the migration_staging migration is applied
From chunk: C0 (T0B-13.C18, lane C0-0B)            To owner: C0-0B (bootstrap) / founder (cloud role)
Type: schema
Blocking? yes — T0B-13.C18 "all migrations apply in order on an empty test database" (LD-202 (e)); push-cloud.ps1 of 20261115180000_migration_staging__create_migration_staging_schema.sql (LD-202 (g)).
Problem: every grant and all 53 policies of C18 05-SCHEMA §2/§4/§5 target `lims_migration`. db/bootstrap/00_roles.sql line 6 reserves the role (DEFER B4, CR-C18-001) and db/tests/roles/00_bootstrap_roles.test.sql asserts it is NOT created. LD-202 (c) forbids touching db/bootstrap, and migrations must not CREATE ROLE (AC-0B-6.3). So on an empty database the new migration fails at its first `GRANT ... TO lims_migration` ("role does not exist") until the role exists.
Proposed change (exact): C18 05-SCHEMA §2 bootstrap part, verbatim, in db/bootstrap/00_roles.sql (provisioning superuser):
  CREATE ROLE lims_migration LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS PASSWORD :'lims_migration_pw';
  GRANT lims_app TO lims_migration WITH INHERIT TRUE, SET FALSE;   -- PROPOSED EXCEPTION D-136
  ALTER ROLE lims_migration SET search_path = '';
  ALTER ROLE lims_migration SET idle_in_transaction_session_timeout = '300s';
  ALTER ROLE lims_migration SET statement_timeout = '30min';
  ALTER ROLE lims_migration NOLOGIN;
  GRANT CONNECT ON DATABASE :"dbname" TO lims_migration;
plus: flip the 00_bootstrap_roles.test.sql assertion to the §2 CI checks (rolbypassrls/rolsuper false, owns nothing, not member of lims_owner / lims_queue, rolcanlogin false); the same role on the cloud project before push-cloud.ps1. Decision needed on the two PROPOSED EXCEPTIONS (policies TO lims_migration §1.2; GRANT lims_app TO lims_migration) — 08 acceptance after B4 (D-136).
Backward compatible? yes — new role only; no existing object changes.
Tenant/security impact: new LOGIN-capable role (NOLOGIN at rest), no BYPASSRLS; RLS on all 16 staging tables with the P-16 guard; REQ-SEC-016/023/042. Inherits lims_app grants (exception).
IRD/regulatory impact: none.
Alternatives considered: (1) CREATE ROLE in the migration — forbidden (AC-0B-6.3, LD-202 (c)); (2) target lims_app — rejected by C18 §1.2 (exposes staging to API/worker); (3) DO block that skips grants/policies when the role is missing — would silently ship staging without RLS policies (deny-all but drift from spec); not done.
Tests that will prove it: db/tests/roles (§2 CI assertions); apply-in-order on an empty DB; pg_prove db/tests/migration_staging/T0B-13.C18_schema.test.sql and T0B-13.C18_behaviour.test.sql; tests/db/T0B-13.C18.migration-staging.test.mjs.
