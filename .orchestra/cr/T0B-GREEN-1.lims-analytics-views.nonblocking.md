Title: CR-C0-T0B-GREEN-1-003: lims_analytics cannot read any v_pub_* view (security_invoker views, no base-table or app-schema grants)
From chunk: C0 (lane C0-0B, T0B-GREEN-1, suite db/tests/anatomic/T0B-13.C11_behaviour.test.sql)            To owner: C0-0B (lead triage; founder decision if the grant model changes)
Type: bug
Blocking? no (LD-268: a REAL defect is not fixed in T0B-GREEN-1; the assertion stays red, unedited)
Problem: test 432 "C11 check 15 / §8 GRANT: lims_analytics may SELECT the view (no permission denied)" gets a permission error. 05-SCHEMA C0 §9 rule 3 and every module migration grant `SELECT ON <schema>.v_pub_* TO lims_app, lims_analytics`, but the views are security_invoker (reloptions {security_invoker=true}, owner lims_owner), so the base tables are read with lims_analytics' own rights, and the same suites (and db/tests/app/T0B-02_helpers) require that lims_analytics has NO privilege on any base table and no USAGE on schema app (the RLS helper functions live there). The two requirements cannot both hold: the grant on the view is dead.
  Evidence (diagnostic run on the pinned image, SET LOCAL ROLE lims_analytics with tenant claims, deleted afterwards): anatomic.v_pub_report_content -> E42501 permission denied for table item_submissions; reporting.v_pub_report_release -> permission denied for table report_versions; instruments.v_pub_agent_status -> permission denied for table agents; micro.v_pub_report_content -> permission denied for view v_pub_report_content; quality.v_pub_qc_summary -> permission denied for view v_pub_qc_summary (the view exists). Same cause for every schema; T0B-GREEN-2 and -3 will meet it again.
Proposed change (exact): lead / founder to decide between (a) the analytics role reads the views as the owner (drop security_invoker on the v_pub_* views and make each view filter by tenant itself), (b) the analytics role gets USAGE on app and SELECT on the base tables under a TO lims_analytics policy with its own tenant predicate, or (c) the grant to lims_analytics is removed from the contract because analytics reads through lims_app / the C8 tables. No DDL is proposed here because each option changes the security model.
Backward compatible? depends on the option; today nothing can depend on the grant because it does not work.
Tenant/security impact: yes, RLS / grant model for the analytics role (REQ-SEC tenant isolation); option (a) and (b) need a security review.
IRD/regulatory impact: none
Alternatives considered: weakening test 432 to check only has_table_privilege on the view (already covered by C11 check 4; refused: it would hide that the view cannot be read).
Tests that will prove it: db/tests/anatomic/T0B-13.C11_behaviour.test.sql assertion 432, plus the equivalent view-read checks of the other modules once added.
