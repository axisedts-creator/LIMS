Title: CR-C0-T0B-GREEN-1-002: app.enforce_mutable_columns rejects every UPDATE of a table with a stored generated column (payments.static_qr_reconciliations.is_active can never change)
From chunk: C0 (lane C0-0B, T0B-GREEN-1, suite db/tests/payments/T0B-13.C15_behaviour.test.sql)            To owner: C0-0B (lead triage; function owner C0, table owner C15)
Type: bug
Blocking? no (LD-268: a REAL defect is not fixed in T0B-GREEN-1; the assertion stays red, unedited)
Problem: static_qr__mutable_columns (20261115150000_payments__create_payments_schema.sql:376) lists is_active, updated_at, updated_by, version as mutable, and the 05-SCHEMA contract says is_active is "the only non-audit column" that changes. `UPDATE ... SET is_active = false` fails with P0001 immutable_row. Cause: the table has a STORED generated column (difference_paisa); a BEFORE ROW trigger sees NEW.difference_paisa before PostgreSQL computes it, so app.enforce_mutable_columns (20261105000200_core__create_tenants.sql:8), which compares to_jsonb(OLD) - mutable with to_jsonb(NEW) - mutable, always finds a difference. Test 373 "C15 test 3: static_qr is_active changes" gets EP0001|immutable_row instead of n=1.
  Evidence: a diagnostic run on the pinned image (deleted afterwards; superuser, rolled back): (1) a temp table (id, a, b GENERATED ALWAYS AS (a*2) STORED, flag) with the trigger app.enforce_mutable_columns('flag') rejected UPDATE SET flag = false with EP0001|immutable_row; (2) a plain INSERT then UPDATE is_active = false on payments.static_qr_reconciliations gave EP0001|immutable_row. So it is the function and not the fixture.
  Other tables with a STORED generated column (grep GENERATED ALWAYS AS db/migrations): core.memberships.is_active (20261105000400:50) and billing (20261105001700:440 balance_due_paisa); the lead should check whether either carries enforce_mutable_columns.
Proposed change (exact): a new migration, either (a) CREATE OR REPLACE app.enforce_mutable_columns to drop the generated columns of TG_RELID from both jsonb values (pg_attribute.attgenerated <> ''), or (b) add 'difference_paisa' to the argument list of static_qr__mutable_columns (the value is derived from two immutable columns, so no information is made writable). (a) fixes the class; (b) fixes this table only.
Backward compatible? yes
Tenant/security impact: none (no RLS change). Without the fix, worksheets cannot be deactivated and the REQ-SEC-016 "class M rows are deactivated, never deleted" path is dead for this table.
IRD/regulatory impact: none
Alternatives considered: changing the assertion to expect immutable_row (refused: it would turn a defect into the contract).
Tests that will prove it: db/tests/payments/T0B-13.C15_behaviour.test.sql assertion 373 (already written; green once the migration lands).
