Title: CR-C0-T0C-10.C11: lint rule 3 cannot express the synoptic `values` map (anatomic.yaml)
From chunk: C0 (T0C-10.C11 writer)            To owner: lead (lint rule 3 / LD-119 allowlist) + C11 (TRD §5.3 ReportDraftInput)
Type: contract
Blocking? no (anatomic.yaml ships `values` as a closed empty object; only C11 report-draft synoptic save/read is affected, which is C11 wave-2 work)
Problem: C11 TRD §4.5.2/§5.3 `synoptic[].values` is `Record<field_key, string ≤4000 | number | boolean | string[] ≤100>` (≤300 keys). Lint rule 3 demands `additionalProperties: false` on every object and OAS 3.0 has no patternProperties, so the only lint-green form is a closed object with no properties — which validates only `{}`. Generated clients / request validation derived from the spec would reject every real synoptic value. Affects saveAnatomicReportDraft request (ReportDraftInput.synoptic[].values) and the ReportDraft response (synoptic[].values; R1, R2, R4).
Proposed change (exact): either (a) lead extends the LD-119 OPEN_OBJECT_ALLOWLIST (tools/codegen/lint-openapi.ts) to request roots and adds entries anatomic/saveAnatomicReportDraft/requestBody `synoptic[].values` and anatomic/{getAnatomicReportDraft,saveAnatomicReportDraft 200, startAnatomicCaseChange 201} `synoptic[].values`, so `values` becomes `additionalProperties: { oneOf: [string ≤4000, number, boolean, string[] ≤100] }, maxProperties: 300`; or (b) C11 TRD changes the wire shape to a list `values: [{ field_key ^[a-z][a-z0-9_]{0,39}$, value }] ≤300` (then c11-openapi.test.ts `values.type === "object"` changes to array).
Backward compatible? yes for (a); (b) changes the C11 wire shape before any client exists.
Tenant/security impact: none; values stay bounded (keys ≤300, strings ≤4000, arrays ≤100); service still validates against the template definition (TRD §4.5.2).
Alternatives considered: JSON-object-as-text (catalog.yaml precedent) — rejected because the C11 test pins `values` as type object.
Tests that will prove it: lint-openapi.test.ts allowlist case for the new entries (a) or c11-openapi.test.ts R2 shape (b); an ajv check that `{ "values": { "syn_field": "x" } }` validates.
