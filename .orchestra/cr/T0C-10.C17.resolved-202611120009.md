Title: CR-C0-0C-006: homecollection.yaml — transitive port-propagated codes (P-23) and device-captured `gps.status` in a sync body (rule 7)
From chunk: C0-0C (task T0C-10.C17, LD-103)            To owner: C0-0C (lint) / program lead (08 A17 P-23, 02-CONVENTIONS §4) / C17 (TRD §5.1 H3, §6.3)
Type: api
Blocking? yes — T0C-10.C17 (contracts/openapi/homecollection.yaml) cannot be lint-green while transcribing the TRD verbatim; C17 plan rows that list homecollection.yaml as a C0 prerequisite wait on it.

Problem:
1. C17 TRD §5.1 H3 `assignHomeVisit` (spec/chunks/C17-home-collection/02-TRD.md:179) lists propagated `catalog.test_inactive`, `catalog.no_price`. C17 does not consume CatalogPort (02-TRD.md:505). The codes reach C17 through `FrontdeskPort.createOrderFromBooking` (C4 propagating C3). 08-CR-REGISTER.md:2378-2379 (A17 P-23) / :985 say "a code thrown by a port propagates unchanged through the calling module ... the caller may list the code in its x-error-codes" and name users C4, C12, C10, C11 only. Whether a code that a port re-propagates (second hop) may be listed by the next caller is not stated. tools/codegen/lint-openapi.ts:138-143 (`errorCodeAllowed`) accepts only owners of directly consumed ports, so it rejects H3 as written.
2. C17 TRD §6.3 (02-TRD.md:266) defines `captured.gps = {status: off|denied|unavailable|ok, ...}` inside the A3 `pushSyncMutations` body (POST /sync/mutations, not an action endpoint). 02-CONVENTIONS.md:425 forbids `status` (outside action endpoints) in client bodies "where the server is the authority". This `status` is a device-captured fact, not server-authority resource status, but the rule's list is literal and lint rule 7 (lint-openapi.ts:235-244) checks every nested property.

Proposed change (exact) — pick one per item:
1a. P-23 text += "This includes a code the port itself propagates from a port it consumes (transitive, e.g. C17 via FrontdeskPort: `catalog.*`)." Current users += C17. errorCodeAllowed: also allow owner O when module consumes port P whose owner consumes a port owned by O (one hop). OR
1b. Delete `catalog.test_inactive`, `catalog.no_price` from C17 TRD H3 error list (clients still receive them as problem codes; they are just not declared).
2a. 02-CONVENTIONS.md:425 clarify: the `status` ban applies to the resource's own lifecycle status (top-level body property), not to nested device-captured observation objects; lint rule 7 checks `status` only at the body root. OR
2b. C17 renames `gps.status` in TRD §6.3 to a C17-chosen name (e.g. as decided by C17 owner — not invented here) and the test follows.
Backward compatible? yes — nothing generated from homecollection.yaml is consumed yet.
Tenant/security impact: none for 1 (codes already reach the client). 2a narrows REQ-SEC-046/013/067 enforcement to body root; a nested `status` on a server-owned resource would then pass lint — prefer 2b if that matters.
Alternatives considered: silently dropping the codes or renaming the field in the yaml (rejected: LD-103 forbids inventing names or diverging from the TRD without a CR).
Tests that will prove it: tools/codegen/__tests__/c17-openapi.test.ts H3 row (:66) and gps test (:642-646) aligned with the decision; lint-openapi tests for the new rule (transitive owner accepted / non-consumed owner rejected; nested `status` accepted only per 2a); `lintRepo` reports no violation.
