Title: CR-C0-0D-T0D-18: module HandlerContext types diverge from 02-TRD §6.3 (LD-133 type loosening) + pipeline wiring gaps
From chunk: C0-0D            To owner: C3/C5 lab, C2 identity, C14 smartreport; C0-0A (deps)
Type: bug
Blocking? no (LD-133: members made optional / loosened in the TYPE only; runtime ctx has every §6.3 member)
Problem:
1. Modules narrow HandlerContext incompatibly with §6.3, so core/module.ts HandlerContext had to loosen these members in the type only:
   - identity (handlers/loginStaff, resolveSession, verifyMfaChallenge, confirmEmailToken, requestPasswordRecovery, setPasswordFromSetup):
     db = { identityAuthTx(input, fn) } (spec: ctx.db.identityAuthTx(fn)); rateLimit / commitOnError optional.
   - lab (handlers/critical, history, ingestException, resultEntry): now?: () => Date (IC §4.1 says IsoUtc string — runtime returns the
     string, so lab code treating it as Date is a likely bug); audit.access(e: Record<string, unknown>); ports/audit optional; tx: object.
   - smartreport (handlers/shared SrCtx, codedSets, denyTerms, library): ports narrowed to { IdentityPort }; tx: object.
   Loosened in core/module.ts: actor.type?, tx: Tx | object, now?: any, ports?: any, db.tx?, db.identityAuthTx?, audit?, rateLimit?, commitOnError?.
2. pg is a devDependency of services/api; the pipeline needs it at runtime when LIMS_CORE_DATABASE_URL is set (C0-0A, LD-05).
3. LIMS_CORE_RATELIMIT_BACKEND=redis (compose default) has no Redis client in services/api deps: boot fails with a clear error (C0-0A).
4. ctx.storage / ctx.uploads / ctx.download answer 503 until the Storage client is pinned (SP-1, T0D-17.nonblocking.md).
5. API has no core-internal 4-arg withTenantScope / systemActorOf: ctx.core.deadLetters.replay answers 500 in the API.
6. CoreDeps for createServices is not defined by 02-TRD §6.3; the core passes { env, log, metrics } [CONV].
Proposed change: owners align their ctx types with §6.3 (then core restores the strict type); C0-0A moves pg to dependencies and adds a Redis client.
Backward compatible? yes
Tenant/security impact: none (runtime enforcement unchanged; type-only).
Alternatives considered: editing modules (forbidden by LD-133).
Tests that will prove it: `pnpm --dir services/api typecheck` with the strict HandlerContext.
