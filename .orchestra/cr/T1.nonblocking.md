Title: CR-C2-T1-a: Patient session kind — LIMS-issued patient access JWT (08 R10)
From chunk: C2            To owner: lead + founder (08 R10; touches 04 A5/A7)
Type: api
Blocking? yes — patient session kind (`provisionPatientMembership`, `openPatientSession`, patient refresh) stays BLOCKED (08 A25 D-218).
Problem: D218_A_CREATE_WITHOUT_EMAIL REFUTED — `POST /admin/users {}` → 400 `validation_failed` "Cannot create a user without either an email or phone". D218_B_CREDENTIALLESS_SESSION REFUTED — no admin route issues a session/JWT for a user; the only admin path (`/admin/generate_link` → `/verify`) needs an e-mail.
Proposed change: per 02-TRD §8 / 08 A25 D-218, amend 08 R10 so patient sessions use a LIMS-issued access JWT (own `session_id`, `aal`, `exp` ≤ 1 h) verified by core alongside GoTrue JWTs. Exact signing key, claim set and core verifier change are for the lead/founder to decide.

Tenant/security impact: new signing key + verifier (REQ-SEC-065/067); no PHI field.
Alternatives considered: synthetic per-patient e-mail (rejected here: invents an address, mail side effects); phone-only users (phone provider disabled; needs SMS vendor).
Tests that will prove it: core JWT verifier tests for the new issuer; C16 patient-session contract tests.

Title: CR-C2-T1-b: REFRESH_REUSE — GoTrue does not revoke the session on refresh-token reuse
From chunk: C2            To owner: C2 (02-TRD §8 redesign note) ; FYI C0 (session revocation)
Type: api
Blocking? no for T1; yes for the AU-T* refresh-reuse acceptance in 07-SECURITY if it requires family revocation.
Problem: on v2.197.0, (1) re-using the immediate parent of the active refresh token after `GOTRUE_SECURITY_REFRESH_TOKEN_REUSE_INTERVAL` is accepted (200, new token); (2) re-using an older token → 400 `refresh_token_already_used`, but the session survives (newest token still refreshes).
Proposed change: on gateway `refresh` → `{ok:false, reason:'reused'}`, the identity service revokes the LIMS session (session_id known from the cookie session) and calls `signOut(lastAccessToken,'local')` when it still holds one; 02-TRD §8 table gets this redesign note. Parent-reuse leniency is accepted as GoTrue design (offline clients) and documented.
Backward compatible? yes.
Tenant/security impact: session theft detection weaker than assumed until the service-side revocation lands.
Alternatives considered: DB delete in `auth.sessions` (rejected: bypasses the gateway, couples to GoTrue internals).
Tests that will prove it: identity service test "reused → session revoked" against the fake; live contract test with a two-step rotation.

Title: CR-C2-T1-c: ADMIN_SIGNOUT — no admin route revokes a user's sessions
From chunk: C2            To owner: C2 (02-TRD §8 redesign note)
Type: api
Blocking? no (workaround in `gateway.http.ts`, live-tested).
Problem: v2.197.0 has no `/admin/...` session/logout route (source `internal/api/api.go`). Ban/unban does not end sessions (live).
Proposed change: `adminSignOutUser` = `GET /admin/users/{id}` → `POST /admin/generate_link {type:magiclink}` → `POST /verify` → `POST /logout?scope=global`. Record in 02-TRD §8 with side effects: overwrites a pending recovery link; counts toward `GOTRUE_SMTP_MAX_FREQUENCY`; adds a login audit row in GoTrue.
Backward compatible? yes.
Tenant/security impact: a recovery link in flight is invalidated when an admin revokes sessions (fail-safe).
Alternatives considered: soft delete (destroys user); DB delete in `auth.sessions` (bypasses gateway).
Tests that will prove it: contract suite `adminSignOutUser` (passes live).

Title: CR-C2-T1-d: GoTrue config values the identity module relies on
From chunk: C2            To owner: C1
Type: bug
Blocking? yes for release (AU-T4 min length, MFA).
Problem: `supabase/config.toml` has `minimum_password_length = 6`, `[auth.mfa.totp] enroll_enabled = false`; upstream compose has `GOTRUE_MFA_TOTP_*` commented out.

API env: `LIMS_IDENTITY_GOTRUE_URL` (internal), `LIMS_IDENTITY_GOTRUE_SERVICE_KEY`.
Backward compatible? yes.
Tenant/security impact: REQ-SEC password policy; MFA availability.
Alternatives considered: none.
Tests that will prove it: `http.live.test.ts` against the C1 stack with `LIMS_TEST_REQUIRE_LIVE=1`.
