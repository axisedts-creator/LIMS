# T18 change request (C2 audit viewer, 2026-11-07) — raised by T18 review item 1

---
Title: CR-C2-T18-a: Audit viewer contract cannot represent DELETE rows or maintenance (NULL-actor) rows
From chunk: C2            To owner: C0-0C
Type: api
Blocking? yes — C2 06-IMPLEMENTATION-PLAN T18 (`listAuditEntries`, `getAuditEntry`; US-D1/US-D2). One such row in a 31-day window makes the whole list page (and that row's detail) off-contract.
Problem:
- `app.tg_row_audit` triggers are `AFTER INSERT OR UPDATE OR DELETE` (e.g. db/migrations/20261105000200_core__create_tenants.sql:124) and `audit_log__action__ck` allows 'DELETE' (db/migrations/20261105000600_audit__create_audit_tables.sql:24). contracts/openapi/identity.yaml `AuditEntrySummary.action` / `AuditEntry.action` (and the `listAuditEntries` `action` query param, identity.yaml:2942) are `enum: [ insert, update ]`.
- 08 A28.5 / A29.2: maintenance DEFINER rows have `actor_type = 'system'`, `actor_id = NULL`. `AuditActor` has `required: [ type, id ]` (identity.yaml:5951), so these rows cannot be serialised.
Proposed change (exact, identity.yaml):
- `AuditEntrySummary.action`, `AuditEntry.action`: `enum: [ insert, update, delete ]`.
- `listAuditEntries` query `action`: `enum: [ insert, update, delete ]`.
- `AuditActor`: `required: [ type ]` (`id` omitted when `actor_id IS NULL`, i.e. `type: system` maintenance rows). Optionally add `maintenance: { type: string, maxLength: 63 }` from `detail.maintenance` — owner decides; C2 will not emit it unless added.
Backward compatible? Response side: widening an enum and relaxing `required` can break strict consumers. Consumers: C2 admin UI (audit viewer) only per 03; no other chunk reads these operations. oasdiff will flag it; owner to classify.
Tenant/security impact: none — no RLS change, no new PHI field, no new surface. Rows are already readable under `audit.log.read` + CR-C2-010 centre clause; the change only lets them serialise.
Alternatives considered: (1) filter DELETE / NULL-actor rows out of the viewer — rejected: hides audit evidence (US-D1, REQ-SEC audit completeness). (2) map DELETE→update or invent a sentinel actor id — rejected: falsifies audit data and invents a value (CLAUDE.md).
Tests that will prove it: C2 service tests (after ruling) with a DELETE row and a NULL-actor maintenance row, list + detail, each validated against the regenerated response schema; contract case added by C0-0C.
