Test: `apps/bridge-agent/internal/queue/queue_test.go:169-178` `TestTamperSwapCiphertextBetweenRows` fails on `mustTamper(t, errB)` (`err = <nil>`). All other queue and secrets tests pass.
Why the test is wrong: the single `UPDATE items SET nonce = CASE ..., ct = CASE ...` reads `items` in its own subselects. SQLite visits row A first and gives it B's nonce/ct; when row B is visited, `(SELECT ct FROM items WHERE id='A')` already returns A's NEW value (= B's own), so B is rewritten with its own bytes. Verified with a scratch test (deleted): after the UPDATE, `B unchanged=true`, `A == old B`. So only A is tampered; B still decrypts correctly under its own row id, as it must. The code is right to return nil for B; `errA` (line 176) passes.
Fix wanted from the tester: do a real swap, e.g. read both blobs first with `rawBlob`, then `UPDATE items SET nonce=?, ct=? WHERE id='A'` and the reverse for 'B' with the saved values (or a single statement using a temp table). Both GetItem calls must then return ErrTampered.
