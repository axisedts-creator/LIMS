1. apps/bridge-agent/internal/svc/platform_windows.go:116-117 and :163-197 (PrepareFolders, ApplyACL, resetToInherited): the owner of the data root and its children is never set. By default, standard users can create folders in C:\ProgramData. A user who creates `C:\ProgramData\LIMS\BridgeAgent` (or `...\LIMS`) before install stays the owner, and an owner keeps implicit WRITE_DAC. After install that user can grant themselves full control and read queue\agent.db and secrets\ (under the S1 machine-scope DPAPI fallback, LD-94, the ACL is the only protection). The user also owns the parent `LIMS` folder, so they can rename `BridgeAgent` away and put their own folder in its place. Fix: in ApplyACL, add `windows.OWNER_SECURITY_INFORMATION` and pass the BUILTIN\Administrators SID (`CreateWellKnownSid(WinBuiltinAdministratorsSid)`) as the owner. In resetToInherited, set the same owner on every walked child. Before touching the root, read the owner of `filepath.Dir(root)` with `GetNamedSecurityInfo(OWNER_SECURITY_INFORMATION)`. If it is not Administrators, SYSTEM or TrustedInstaller, either fail closed with a clear error or take ownership with the same call. TESTER: add a windows_integration test that pre-creates the root and asserts that the owner is Administrators after PrepareFolders.
