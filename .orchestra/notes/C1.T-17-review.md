2. infra/logging/fluent-bit/scrub.lua:79 — `scrub_phones` checks only that the character after the 10th digit is not a digit. Letters are allowed after the match and `-` is allowed between digits, so it rewrites UUIDs. 02-CONVENTIONS §9.2 says UUIDs must stay intact in logs, and the file header promises the same. Example: `0b1c2d3e-9123-4567-89ab-cdef01234567` becomes `0b1c2d3e-[PHONE]ab-cdef01234567`. A match can also start at the first or fourth group. Together that hits roughly 0.2 % of v4 ids (patient_id, order_id, request ids) and breaks log correlation for them. Fix: change line 79 to `if count == 10 and not is_alnum_at(s, last + 1) then`, so the character after the number must not be a letter or digit, the same rule as the check before it. Add a behaviour test to test_t17_logging.py that passes `0b1c2d3e-9123-4567-89ab-cdef01234567` and `9123abcd-1234-4567-89ab-123456789012` and expects both unchanged, next to the existing phone cases (`9841234567`, `+977-9841234567`), which must still be redacted.
