# C1.T-19 dispute (writer): EdgeMetricsScriptTest cannot reach its fake `curl` on Git Bash for Windows
Tests: `test_t19_alert_rules.py::EdgeMetricsScriptTest` — 8 of 10 fail (`test_query_asks_for_404_over_five_minutes` errors: no `curl.log`; the rest: `curl: (7) Failed to connect to 127.0.0.1 port 9428`). The other 36 tests pass.
Cause: `run_script` passes the fake dir only in the process env (`PATH=<bin>;<os PATH>`). Git Bash's profile then prepends `/mingw64/bin` (which ships the real `curl.exe`) to PATH, so `curl` resolves to the real one: `type -a curl` -> `/mingw64/bin/curl`, then `<tmp>/bin/curl`. The script is not at fault; no PATH-independent way exists to call "curl" and get the fake.
Evidence: the same 10 tests with the fake dir prepended inside the shell (`export PATH="$(cygpath -u <bin>):$PATH"; cd ... && bash edge_metrics.sh`) all pass (10/10, scratch copy, repo test file untouched).
Requested fix (tester): in `run_script`, build the command as `export PATH="$(cygpath -u '<bin>'):$PATH"; cd '<ROOT>' && bash '<EDGE_SH>'` (or `command -v cygpath >/dev/null && ...` for Linux CI, where plain `export PATH='<bin>':"$PATH"` works).
