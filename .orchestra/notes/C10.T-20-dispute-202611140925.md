# C10.T-20 dispute (writer)

Four test defects. Each cannot pass with ANY implementation built on the kit; I did not edit any test. Evidence = real runs of `.orchestra/notes/C10.T-20-verify.cmd`.

1. **t20.reads.test.tsx lines 96, 120, 128, 143, 153, 162 (×3 `it.each`), 180, 190, 205, 259 — screen never mounted.** `openRead()` / `openStain()` (lines 31–32) only click a button then wait for a dialog; these tests never call `mount()` first. Result: empty `<body />`, `Unable to find role="dialog"`. (Line 105 and the refusals block do call `mount()` and open the dialog fine.) Fix: start `openRead`/`openStain` with `if (screen.queryAllByRole('tab').length === 0) await mount();`.
   Check: with that one-line change in a temporary copy, all 23 reads tests pass against the implementation.

2. **t20.setup.test.tsx `openSetup` (line 42 etc., 18 tests) — `findByText(/synthetic urine protocol/i)` matches two nodes.** The kit `Select` renders the chosen label in `SelectValue` AND a hidden native `<option>` (react-aria HiddenSelect), so `findByText` throws "Found multiple elements". Any kit Select showing the suggested protocol does this. Fix: `findAllByText(...)`. With that change in a temporary copy 33/35 setup tests pass (the other two below).

3. **t20.setup.test.tsx line ~288 (`POST /plates … parent_plate_id`): `pick(d, /parent plate/i, /./i)` uses `findByRole('option', {name: /./})`.** The test itself mounts two active plates, so two options match and `findByRole` throws "multiple elements". Fix: pick by name, e.g. `/plate 1/i`.

4. **t20.isolates.test.tsx** — two tests:
   a. line 52, AC-05.5: `within(r).getAllByRole('gridcell')[0]` is expected to be the Isolate no. cell. Test 'single selection' (same file) requires kit `selection`, which adds a selection cell as the first gridcell (text ''). Both cannot hold. Fix: read the cell by column index 1 or by header.
   b. line 170 (organism typed but not chosen): after typing "free typed organism" the Combobox popup is open (`aria-expanded=true`), and react-aria sets `aria-hidden` on everything else in the dialog, so `getByRole('button', {name: /save/})` finds nothing before the click. Kit behaviour (`allowsEmptyCollection`). Fix: press Tab/Escape or blur the box before looking up Save, or use `{ hidden: true }`.

**Seam notes (not disputes):**
- Tests anchor on `/^plate/i`, `/^medium/i` for kit Select triggers, whose accessible name is "{value or placeholder} {label}". I gave those Selects placeholders that start with the label ("Plate…", "Medium…", "Growth…", "Plate (optional)", "Parent plate (optional)") so the anchored regexes match.
- Medium / Plate / Growth "required" use the text "Choose a …" (not the kit's "Enter …") because tests match `/choose|select|required/`.
