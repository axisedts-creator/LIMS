# C11.T-10 dispute (writer) — fixture contradicts AC-12.6
Test: `services/api/src/modules/anatomic/__tests__/images/images.handlers.test.ts`, `seed()` (lines 248–253) vs the I1 tests that upload to `CASE.OPEN`.
- `seed()` sets `settings.max_images_per_case = 3` and puts FOUR active images in `CASE.OPEN` (READY, JPEG, PROCESSING, QUARANTINED; all `is_active: true`).
- AC-12.6 / TRD §4.9: "case already has `max_images_per_case` active images -> 422 `anatomic.image_limit_reached`". 4 >= 3, so every I1 upload to `CASE.OPEN` is refused. The same tests also expect 2 uploads in a row on OPEN (path-rule test) and 201s on a case that already holds > 3.
- No counting rule satisfies both: ready-only = 2 (the 2nd upload in the path test then hits 3); excluding quarantined = 3 (refused at once). The spec says "active", nothing narrower.
- Result: 25 of 69 api tests fail, ALL with `anatomic.image_limit_reached` (10 as thrown error, 15 as the wrong code in `codeOf`). Worker side passes 36/36. With the limit check removed the rest of I1–I4 was not separately run.
- Fix (tester): seed a high `max_images_per_case` (e.g. 50) and let the AC-12.6 tests set `S.settings.set(T, {..., max_images_per_case: 3})` themselves on `CASE.LIMIT` only (use a fresh case with no other images; the "per-case unaffected" test must then upload to a case with < 3 active images, not OPEN).
