# C11.T-22 dispute (writer)
**Wrong tests:** 32 of 122 fail on one selector defect, in `t22.molecular.test.tsx` (25) and `t22.batches.test.tsx` (7). Nothing else fails: `t22.source.test.ts` 27/27 pass.
**Defect:** the tests find kit `Select` buttons with anchored names: `/^assay/i`, `/^target/i`, `/^result/i`, `/^batch/i`, `/^status/i` (helpers `choose`, `btn`, direct `getByRole('button', { name })`). The kit `Select` (packages/ui/src/components/Select/Select.tsx) renders `<button aria-labelledby="{SelectValue id} {Label id}">`, so the accessible name is "<selected text or placeholder> <label>", e.g. "Select an item Assay" or "Synthetic PCR A Assay". It never starts with the label, so `^assay` cannot match. I checked this in jsdom: `/^assay/i` finds 0 buttons, `/assay/i` finds 2 (both selects with that label). The harness header says "kit Select = button named by the label"; that is true only as a substring.
**Why I cannot fix it in code:** the kit is not mine, and every kit-only alternative gives the same name order. A `placeholder` hack would break once a value is chosen ("changing the assay clears target + result" re-opens an already-filled Assay select). Prefixing option labels would break `/^Detected/` and the `Select …` checkbox names.
**Evidence the implementation is otherwise right:** I ran copies of the two files with only the anchors removed (`/^assay/i` to `/assay/i`, same for target/result/batch/status; the copies were deleted afterwards). Result: molecular 39/39 and batches 56/56 pass. T-19 (265) and T-20 (191) suites still pass.
**Fix requested (tester):** drop the `^` on those five names in both files (label substring match is unambiguous inside a row or dialog), or scope with `within(row)` plus `{ name: /assay/i }`. No behaviour assertion needs to change.
