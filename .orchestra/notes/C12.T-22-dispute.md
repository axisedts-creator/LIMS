# C12.T-22 dispute (writer)
Result: 189 of 197 pass. The other 8 (all in `t22.purchasing.test.tsx`, describe "S6 detail of a non-draft PO and its actions") fail for ONE reason, which is a test defect.

**Defect.** The tests look up the PO action "Close" with `within(dlg).queryByRole('button', { name: /^close$/i })` (lines 487, 498–499, 588, 603). `dlg` is the Drawer dialog, and the kit Drawer always renders its own dismiss icon button `aria-label="Close"` (packages/ui `OverlayFrame`: `<IconButton label={msg.close} icon="close">`; `DrawerProps` has no way to hide it). So inside `dlg` there is always one button named "Close", whatever the PO state.
- "absent" assertions (`approved`, `sent`, `closed`, `cancelled`, and "Cancel / Close need inventory.po.manage — hidden for an approve-only user") can never be true: they receive the kit X button.
- "present" assertions (`partially_received`, `received`, AC-05.6 close flow) throw "Found multiple elements with the role button and name /^close$/i": the kit X plus the PO "Close" action.
- Verified in the failure output: the received element is `<button aria-label="Close" class="lims-btn lims-btn-ghost lims-icon-btn">` with the X svg.

**Why the implementation is right.** The S6 state table (04-UI-UX §3 S6) names the action "Close"; `PoDetail.tsx` shows it only for `partially_received` / `received` with `inventory.po.manage`, hides it for every other state and for an approve-only user. The action opens the ConfirmDialog "Close purchase order" with the confirm button "Close PO" (this part of the tests passes: reasons from `reason_group=po_close`, body `{reason_code}`, Idempotency-Key + If-Match are covered by the same test that fails only on the first lookup).

**Fix wanted in the tests (tester).** Scope the lookup to the dialog content, e.g. `dlg.querySelector('.lims-dialog-content')` instead of `dlg`, or exclude the kit dismiss button (`.lims-icon-btn` / `getAllByRole(...).filter((b) => !b.classList.contains('lims-icon-btn'))`). The same query on any other kit overlay would collide in the same way.

I did not rename the PO action (a different name breaks the S6 spec) and did not touch kit code (not owned).
