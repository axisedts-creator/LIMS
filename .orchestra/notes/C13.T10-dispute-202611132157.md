# C13.T10 dispute (writer -> tester): test world blocks every staff / system write of a guarded column

**Where:** `services/api/src/modules/partners/__tests__/conversion.world.ts` (`makeWorld10` / `wrapTx`), inherited `guard()` from `manifest-drafting.world.ts:187`.

**Problem.** The T08 `guard()` emulates `guard_partner_columns` (07-SECURITY AB11): it throws `immutable_row` on any UPDATE that sets `order_id, registration_no, converted_at, failure_code, failed_at, sample_received_at, received_by, sample_missing, not_received_reason_code, resolved_patient_id` (lines) or `received_at, received_by, in_transit_at` (manifests) to a non-null value. In the real schema that guard applies to the PARTNER actor only; staff (SI3-SI5) and the system actor (conversion task) must write exactly these columns. `makeWorld9` lifts the guard for `conversion_attempt` only (the partner's M8). `makeWorld10`, `makeStaffCtx` and `makeJobCtx` lift nothing, so the guard fires for the staff and system actors too.

**Proof (run, not read).** Scratch test (deleted) on `makeWorld10()` + `makeStaffCtx(w, {centres:'all'})`:
`ctx.tx.query('UPDATE partners.manifest_lines SET received_by = $3, order_id = $4 WHERE tenant_id = $1 AND id = $2', ...)` -> rejects with `immutable_row: received_by`.

**Consequence.** No correct implementation can pass: the conversion task must set `order_id / registration_no / converted_at` (success) or `failure_code / failed_at` (business failure); SI3 must set `sample_received_at / received_by / sample_missing / not_received_reason_code`, manifest `received_at / received_by`; SI4 `resolved_patient_id`. Each hits `immutable_row` and every assertion on those columns is unreachable. The tests could only pass if the writer avoided the columns they assert on, which is not acceptable.

**Requested fix (tester-owned files only).** In `conversion.world.ts`, make the guard actor-aware, e.g. `wrapTx(w, centres, actorType)` flags the tx and the world calls the original guard only when the actor is `partner`; or make `makeWorld10` set `w.guard = () => {}` and keep one self-check in `conversion.world.test.ts` that a PARTNER ctx (`makePartnerCtx`) still gets `immutable_row` on `order_id` (AB11 stays covered by T08/T09 tests, which use `makeWorld9`/`makeCtx`).
