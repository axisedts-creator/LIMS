TESTS_WRONG — both disputed failures are test defects: (1) the conversion test world rejects the `SAVEPOINT`/`ROLLBACK TO`/`RELEASE` SQL that the spec-mandated savepoint needs; (2) staff-receipt.test.ts:412 omits the seeded manifest M.xs from the `has_missing_samples=false` list.
Reasons:
- spec/program/08-CR-REGISTER.md:2636 (P-44) and spec/chunks/C13-b2b-partner-portal/03-APP-FLOW.md:166-168 require a real C0 `SAVEPOINT`/`ROLLBACK TO` around `createOrderFromBooking`, so that "the marker is absent after commit" (07-SECURITY.md:122 ST18). The spec mandates the outcome. It does not say savepoint SQL may only arrive through the `ctx.db.tx` callback. In production the worker's `ctx.db.tx` is `fn(ctx)` with no savepoint (services/worker/src/core/consumer.ts:58), so issuing SQL savepoints on `ctx.tx` is a spec-faithful way to meet P-44. The worker's real-PG convert-savepoint.test.ts asserts that it does.
- Required change 1 (conversion.world.ts `wrapTx`, :104): accept `SAVEPOINT <name>` (push snap(w) onto a named stack), `ROLLBACK TO [SAVEPOINT] <name>` (restore that snapshot and keep the savepoint), and `RELEASE [SAVEPOINT] <name>` (pop it). Keep the existing callback-level savepoint in ctx.db.tx. Add one self-check: marker written after `SAVEPOINT`, then `ROLLBACK TO`, means the marker is absent and earlier rows remain. The marker-row assertions (ST18) and every other conversion assertion stay unchanged.
- spec/chunks/C13-b2b-partner-portal/05-SCHEMA.md:246,589 and 01-PRD.md:142 define `has_missing_samples` as "a line with `sample_missing AND state = 'converted'`". `false` is the complement, so M.xs (submitted, no such line) belongs in it. staff-receipt.test.ts:393,394,399 already expect M.xs in the other unfiltered lists.
- Required change 2 (staff-receipt.test.ts:412): add `M.xs` to the expected `false` set: `[F['id'], C['id'], N['id'], M.xs].sort()`. The `true` assertion at :411 stays unchanged.
- Info for the lead (not part of this ruling): consumer.ts:58 `db.tx` has no savepoint, which falls short of the "C0 SAVEPOINT" wording in P-44. That file is owned by C0, so a C0 follow-up may be needed for other ports.
