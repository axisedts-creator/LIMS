TESTS_WRONG — the test asserts something the spec does not require (say precisely what to change in the test)
- Ruling on dispute #2. All 8 failures come from test mechanics. The spec does not require any of the behaviours they assert.
1. sr-t20.texts.test.tsx:97, :98, :147 (through fillValid :41). The spec only needs the typed text to arrive as written (04-UI-UX.md placeholder chips; AC-03.4). user-event v14 reads `{x}` as a key descriptor, so the placeholder text is never typed. Fix: escape each literal brace as `{{` in the it.each texts and at :147 (`'Take {{dose} daily'`, `'{{test_name} is high'`, `'{{analyte_name} is above…'`), or have fillValid set the text with `userEvent.paste`. The :151 assertion keeps the unescaped value.
2. texts.test.tsx:179 and mapping-rules.test.tsx:38. The word `alertdialog` appears nowhere in spec/. Spec only names `ConfirmDialog` (C0 04-UI-UX.md:221; C14 04-UI-UX.md:129), and the kit renders that with role="dialog". Fix: query `screen.findByRole('alertdialog').catch(() => screen.findByRole('dialog'))` in both places.
3. mapping-rules.test.tsx:195-203 (AC-05.3). Each loop pass calls openRules → showEditor (harness.tsx:148), which mounts the page again without cleaning up first, so the tabs end up duplicated. Fix: call `cleanup()` at the end of each iteration.
4. editor.test.tsx:228-232. C14 04-UI-UX.md:121 asks only that each row action jumps to its tab. Nothing in the spec says the issues grid stays mounted. Fix: query the grid again on every call: `const acts = () => within(gridNamed(/issues|checks/i)).getAllByRole('button');`.
