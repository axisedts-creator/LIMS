# T-29 dispute (writer)
Two tests in `contract/CatalogPort.t29.parties.test.ts` cannot pass for any correct impl:
- "getReferrer ... bad input" and "getCreditParty ... bad input" call `ref(id, undefined)` / `party(id, undefined)`. The helpers declare `purpose: unknown = 'display'`, so an explicit `undefined` becomes the default `'display'` and the call is VALID (JSON.stringify shows `"purpose":"display"`). The case "missing purpose" is therefore never sent.
- Fix (tester): build the missing-purpose input without the helper, e.g. `{ referrerId: id }` / `{ creditPartyId: id }` (those cases are already in the lists), and drop the `undefined`-purpose entries.
Impl rejects a truly missing/unknown purpose with `common.validation_failed` (checked by the `{ referrerId }` / `{ creditPartyId }` entries, which pass).
