# C6-T30 dispute — AC-10.2 test "unknown / revoked / unreleased / malformed: status, headers and body identical" (spec.ts:311)

47/48 E2E pass. This one cannot pass with any Next.js page (spec skeleton: `v/[token]/page.tsx`, "server-rendered") and the test's own normaliser.

Measured (3 tokens, `/v/<tok>`, dev server): status and all headers/body are identical EXCEPT per-request randomness Next itself emits:
1. `Link` header: `...; rel=preload; as="style"; nonce="<per-request nonce>"` and body `<script nonce="...">`. `norm()` runs on `JSON.stringify(...)`, where these appear as `nonce=\"...\"`; its regex `/nonce="[^"]*"/` needs `nonce="` and never matches the escaped form (only the CSP `nonce-...` form is normalised).
2. Body `self.__next_r="<random id>"` — generated by Next for every render; not controllable by the app.

The nonce is required by REQ-SEC-089 (spec/test `nonce-${` in middleware). No information about the token leaks: the writer already makes the payload token-independent (middleware rewrites `/v/<tok>` to `/v/_`, token travels in a request header; 404/malformed/unknown all take the same path; a 4-token diff shows only the items above).

Ask: tester to normalise `nonce=\\"...\\"` and `__next_r="..."` (or compare after JSON.parse), or drop the Link/body-nonce comparison. Alternative (writer, costly, spec deviation): serve `/v/*` from a raw-HTML route handler with no scripts/nonces — not done without a lead ruling.
