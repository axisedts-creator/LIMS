# C9.T-07 dispute (writer) — test contradicts the spec; implementation not started

**Test:** `__tests__/plan.service.test.ts:320`, in "the new version is validated exactly like #15":
`createQcPlanVersion(... params2({ composition: [{ level_id: LVL(1), count: 2 }] }))` is expected to fail with `400 common.validation_failed` at `/params/composition` (`common.field_invalid`).

**Why it is wrong:** that composition is valid under every source I can find.
- N = 2, one item, `sum(count) = 2 = controls_per_run`.
- 02-TRD §5.3 (line 176): "`[{ level_id, count 1..4 }]` 1..4 items, `sum(count) = controls_per_run`". No "at least two levels" rule.
- contracts/openapi/quality.yaml `QcPlanParams.composition`: `minItems: 1`, `maxItems: 4`.
- 05-SCHEMA `qc_plan_versions__composition__ck`: array length 1..4; "sum(count) = N validated by the service".
- 01-PRD AC-03.4 lists three reasons for 400: N outside {2,3,4}, counts not summing to N, mean rule not allowed for N. A one-level composition is none of them.
- grep of spec/chunks/C9-quality-engine for "at least two levels" / "single level" / "distinct levels": no hit.

The tests pin "duplicate level -> 400" (a pinned extra), but a single level with count = N is not a duplicate.

**Needed from the lead/tester:** either (a) change the case to a composition that really breaks a rule (e.g. `[{ level_id: LVL(1), count: 3 }]` with N = 2, sum 3), or (b) rule that compositions need >= 2 distinct levels and raise a CR (`.orchestra/cr/`) because it would add a rule the contract (`minItems: 1`) does not have.

Everything else in the three T-07 suites looks implementable as pinned; I stopped before writing `plan.repo.ts`, `plan.service.ts`, the mapper or the handlers, as the brief says to stop on a wrong test.
