## 1. tat.repo.sql.test.ts line 77 — `updateItems` tenant pin contradicts the SET pin
`expect(s).not.toMatch(/\bSET\b[^;]*\b(tenant_id|created_by)\s*=/i)` vs line 41 (every statement matches `/tenant_id\s*=\s*\$\d+/i`).
In an UPDATE the tenant predicate (`WHERE t.tenant_id = $1`) always follows SET, and `[^;]*` spans the whole statement (`;` is forbidden by `/;\s*\S/`): the negative regex matches the WHERE clause, so both pins cannot hold.
Intent (SET never assigns tenant_id / created_by) is met: only the SETTABLE allow-list is assigned, other columns throw before a statement (line 80 passes).
Fix: bound the check to the SET list, e.g. `/\bSET\b(?:(?!\bWHERE\b)[\s\S])*\b(tenant_id|created_by)\s*=/i`.
