TESTS_WRONG — the six identity *.handlers.test.ts suites build a handler ctx without `ports.IdentityPort`, so they exercise a pre-SEC-AUTHZ-4 handler that the approved design no longer allows.
Reasons:
1. The approved design (LD-261 approves .orchestra/cr/SEC-AUTHZ-1.1.nonblocking.md as written) says the operation's x-permission is checked with `IdentityPort.assertRole(ctx, { permission })` before the handler runs (CR :9, :21, :63, :83). The task brief done_when adds that "every denial happens before any data is read or written".
2. A deny returns only the error assertRole throws (CR :69, :89). A guard that skips when the port is missing would let the handler run with no check, which is fail-open and goes against CR :21 ("a control, not a detector"). Failing closed with the existing `common.internal` (CR :19, :47 use it for a missing assert) adds no new error code.
3. So the guard calls the port before the binder's own context check. The old expectations (200 + ETag, auth.unauthenticated on an empty ctx, identity.self_action_forbidden) are still correct once the guard allows the call. They just need a ctx that has the port.
What the tester changes: in the ctx fixtures/helpers of user, role, org, settings, self and tenant-access (*.handlers.test.ts plus their helpers.ts), add `ports: { IdentityPort: { assertRole: async () => undefined } }`, including in the "no context -> auth.unauthenticated" cases. Do not change any expectation. Denial behaviour stays covered by authz4.identity-guards.test.ts.
