TESTS_WRONG — the tests assert things the spec does not require and call functions pgTAP does not have; the implementation stays as it is.
1. T0B-10.C4_schema.test.sql:75. The spec requires the source predicate `centre_id = ANY ((SELECT app.current_centre_ids())::uuid[])` (spec/chunks/C4-frontdesk-billing/05-SCHEMA.md:75, :77, :1416). It does not require that exact text to survive in pg_policies, and PostgreSQL deparses the subselect as `( SELECT app.current_centre_ids() AS current_centre_ids)::uuid[]`. Change the regex to `current_centre_ids\(\)( AS current_centre_ids)?\)::uuid\[\]`.
2. Same assertion (:75-76): the `tpl IN ('TC','TCN')` join also picks up `trf_attachments__{select,delete}__owner_only`. By spec those two policies have no centre predicate (05-SCHEMA.md:86, :490-495; USING is maintenance + order_id IS NULL + tenant only). Add `AND p.policyname !~ 'owner_only'` to the WHERE.
3. T0B-10.C4_behaviour.test.sql: pgTAP has no `like()` or `unlike()`. Its LIKE-pattern assertions are `alike(have, pattern, desc)` and `unalike(have, pattern, desc)`, and nothing in db/ defines a `like`/`unlike` helper. Replace every `SELECT like(` with `SELECT alike(` (lines 138-141, 147-149, 151, 154, 169, 182, 188-218, 258, 263, 276-278). Replace `unlike(` with `unalike(` at :174, which the dispute did not list. Keep the patterns and descriptions unchanged.
4. Rerun the whole behaviour suite after the rename. Report any failures in tests 210+ as a new round. This ruling covers only the three defects above.
