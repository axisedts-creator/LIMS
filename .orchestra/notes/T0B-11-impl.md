# T0B-11 impl (writer)
- Added `db/tools/export-tenant-billing.ts`. It finds every `billing` table with a `tenant_id` from pg_catalog, so new tables are picked up with no code change; `g_*` and other tables without tenant_id are skipped. For each row it writes `INSERT INTO billing.<t> (<non-generated cols>) SELECT … FROM json_populate_record(NULL::billing.<t>, '<row json>')`. The script is built on the server via psql `\gexec`, and the tenant is passed as a psql variable (`:'tenant'`).
- [CONV] Follows `policy-dump.ts`: host psql, DATABASE_URL, exits 0/1/2. The tenant UUID is checked before any connection. Output is written only after psql succeeds. Read-only is set through `PGOPTIONS default_transaction_read_only=on`. If psql fails, the DATABASE_URL is masked in stderr.
- Tests: `node --test tests/db/T0B-11.billing-export.test.mjs` passes 18/18 on 3 runs. One earlier run had a single test die with Windows exit 0xC0000409 (node crash, empty-PATH env); it did not happen again.
- I ran the tool's own SQL by hand through docker psql on postgres:17 with a scratch fixture (generated column, jsonb, text[], quotes and backslashes, an A/B tenant pair, a g_ table, and a column named `x`). Export, restore into a LIKE clone, and md5 compare all matched, and no B row was exported. This caught and fixed two bugs: a format() argument mismatch, and the alias `x` colliding with a column named `x`.
- NOT run: `db/tests/billing_isolatable/T0B-11_billing_isolatable.sh` (AC-0B-6.4 live), because there is no host psql here. Typecheck was not run because @types/node is missing for a standalone tsc.
- Open: rows come out in table-name order, not FK order, so restoring into the real DDL (with FKs and triggers) may need FK ordering or deferred constraints. The connecting role must bypass or satisfy RLS, otherwise the export is silently short. The whole export is held in memory (marked with a ponytail comment).
