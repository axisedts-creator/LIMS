Prescribed API (names are mine, internal only, no spec name): RawStorage.getStream/putStream; StorageAdapter.readStream({range:{start,end}})/putStream(..,{maxBytes}); core/storage/stream.ts `streamStored(storage,{bucket,objectPath,headers,cache?,requestHeaders?})`; DownloadInput.requestHeaders + cache (`'no-store'` default | `{privateMaxAgeSeconds}` 1..3600); IncomingFile may carry `stream` + `declaredSize` instead of `bytes`. Body = Node Readable when storage can stream, else the old Uint8Array (existing fakes keep passing).
Decisions pinned: 304/206/416 per RFC 9110; multi-range or malformed Range is ignored (200); access log row for 200/206/304, none for 416; default cache-control stays exactly `no-store` (existing tests pin it); memory = retained heap+Buffers after forced gc, <= 20 MB for 50 MB download, 50 MB putStream, 50 MB engagement fetch, 50 MB body cut at a 5 MiB accept limit.
Expected buffered in accept (implementer must say so in notes): PNG re-encode (REQ-SEC-083..085), CSV UTF-8/NUL, anything with scan=required (scanner takes bytes; max 15 MiB, at most one copy, tested <= 20 MB for 8 MiB).
Not covered: TRF module behaviour is static only (its tests need the DB); portal P4 is static only; real HTTP multipart layer does not exist in the API yet (accept is fed by the caller); S3 putStream wire details beyond "streamed body, create only".
