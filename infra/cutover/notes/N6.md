Files: `infra/cutover/bootstrap.sh`, this note. `bootstrap.sh [--dry-run] [--rollback]`; env var table in the script header.

- Steps 1-12: packages, ansible-core (venv `/opt/lims/ansible-venv`, version read from THIRD-PARTY-OPS.md), sops (MANUAL), local override, age key, secrets, site.yml, images (MANUAL), site.yml again, db-bootstrap.yml, `infra/ci/deploy.sh staging`, smoke hint. Prechecks first (Ubuntu LTS, root, >=16 cores, >=30 GiB, env, staging-lean `dr: {}`/`backup: {}`, disks).
- Exit: 0 ok, 1 FAIL, 2 refused (wrong LIMS_ENV/inventory/usage, also in dry-run), 3 MANUAL pending (non-interactive). [CONV] `--dry-run` reports failed prechecks as `would FAIL` and still exits 0 (a real run exits 1).
- [CONV] Local connection without touching the repo inventory: a generated `ansible-playbook` shim in `/etc/lims/bootstrap/bin` (first on PATH) adds `-c local -e @extra.yml` (secrets_render_enc_file, acme_mode, acme_email, origins). It lets `infra/ci/deploy.sh`/`rollback.sh` run unchanged. deploy.yml runs via deploy.sh (inventory, lock digests, smoke, auto-rollback), not by hand.
- [CONV] Disks: `hosts.yml` placeholders are NOT edited. `LIMS_DISK_<KEY>` (DB, REPO1, STORAGE, DATA) or an up-front prompt over a whole-disk listing of /dev/disk/by-id; each must exist, be a whole disk, unmounted (except /srv/lims/*) and unique. Written as extra var `disks` in extra.yml (beats the inventory). Placeholder + no answer = `would ASK` (not a FAIL). `server-smoke.sh` luks-mounts still reads hosts.yml disks (not mine): it will see the placeholders.
- [CONV] Names I chose: `LIMS_ACME_EMAIL`, `LIMS_ACME_MODE` (default `staging`), `LIMS_SECRETS_DIR` (default `/root/lims-secrets-work`, as CUTOVER.md), `LIMS_RELEASE`, `LIMS_LUKS_PASSPHRASES_FILE`, `LIMS_RUNTIME_IMAGES_FILE`, `LIMS_WHEELHOUSE`, `LIMS_BOOTSTRAP_NONINTERACTIVE`. Reused: `LIMS_ORIGIN_*`, `SOPS_AGE_KEY_FILE`, `LIMS_INVENTORY_DIR`.
- [CONV] Secrets: age-keygen at the chosen path; `.sops.yaml` in the secrets dir = copy of `infra/secrets/.sops.yaml` with the staging recipient set (repo file untouched); values via the kit's role `secrets_render` `tasks_from: generate`, driven by a 10-line generated wrapper playbook (the kit has no playbook for it). Never regenerates an existing `staging.enc.yaml`. Local git repo only; the bare repo on ops-1 (02-TRD 8.2) is not made.
- MANUAL steps (print exact text, wait; non-interactive exit 3): install sops 3.13.3 (no kit installer, not an apt package); age key custody; build + push images, `release-lock`, write the `lims_runtime_images` file (no kit converter lock -> variable).
- OPEN for the lead: `site.yml`'s last play (lims_runtime) fails closed without image digests, but the registry that receives them comes from the same `site.yml`. The script treats a stop at `lims_runtime : Preconditions` (no images file yet) as "partial", then step 8 (MANUAL) and step 9 (rerun). CUTOVER.md 2.8 says the runtime is "held back"; the kit actually fails.
- LUKS passphrases: asked hidden once per blank disk, written to tmpfs `/run/lims-bootstrap`, deleted on exit; never in answers.env or logs.
