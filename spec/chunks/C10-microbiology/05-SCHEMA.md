# C10 Microbiology — 05 Schema (`micro`) — specification for C0-0B

Status: DECISION, 2026-11-06. C0 implements this as DDL in `db/migrations/` and policies in `db/policies/micro.sql` (01 §0, §3). C10 never edits `db/`. Names follow 02-CV §3. Wire/JSON field names = column names (snake_case).

Rules applied: tenant tables carry `tenant_id uuid NOT NULL` without default (04 D1); UUIDv7 ids from app code, no DB default (04 D9); composite `(tenant_id, id)` FKs (04 D8); `tenant_id` leads every index and unique key (02-CV §5.3); no Postgres ENUM (02-CV §5.5); RLS ENABLE + FORCE, per-command policies `TO lims_app`, helpers wrapped in `(SELECT …)` (02-CV §5.8); class C/A/M tables have no DELETE grant; the class E table `instrument_records` is deleted only by its retention task (02-CV §5.6; 08 A17 P-18, D-65); AST interpretation is a global extensible coded set (04 D14).

**Centre scoping decision** (02-CV §5.8 "chunk decides"; 08 A17 D-63): Visibility = all centres, or `centre_id` (the collection centre from the event, copied onto every culture and child row at insert) among the actor's centres. Hub microbiology staff follow 08 A13 D-13(2), extended to holders of `micro.culture.read`/`micro.culture.work`: they need `all_centres = true` or membership of every collection centre whose samples they process. No `micro` table has `processing_centre_id` or `processing_branch_id` (review m#36: the branch column had no reader and is dropped). Child rows (`culture_transitions`, `culture_plates`, `culture_observations`, `isolates`, `ast_results`, `report_versions`) copy `centre_id` from their culture at insert; `centre_id` never changes, so culture and child visibility cannot diverge. `instrument_records.centre_id` = the instrument's centre (event `centre_id`).

## 3. Coded sets and seed data

### 3.3 Coded-set resolution views (internal)

`micro.v_<set>` = tenant rows `UNION ALL` global rows whose `code` has no tenant row, with `source ∈ {tenant, global}`; `security_invoker = true`; used by repositories and `listMicroCodedSet`. Validation of a code everywhere = "exists in `v_<set>` with `is_active`" (or is the currently stored value).

## 4. RLS (02-CV §5.8 template)

- Centre predicate `pred_c`: `tenant_id = (SELECT app.current_tenant_id()) AND (SELECT app.current_actor_type()) IN ('user','system') AND ((SELECT app.has_all_centres()) OR centre_id = ANY ((SELECT app.current_centre_ids())::uuid[]))` (08 A17 D-63: collection centre only; 08 A16.1 cast). The actor-type term is needed because 02-CV §5.8 `current_centre_ids()` returns `[claims.centre_id]` for **device** actors and `is_staff_or_system()` counts devices as staff (review m#30); partner/portal/patient actors fail it too.
- Tenant predicate `pred_t`: `tenant_id = (SELECT app.current_tenant_id()) AND (SELECT app.is_staff_or_system())` — written into the transcribed DDL variable, not only here (08 A17 P-16; CR-C13-011 / 08 R10). No `micro` table is shared with partner/portal/patient actors.
- SELECT + INSERT policies on every tenant table; UPDATE policy + grant only where marked `u` in the §8 loops. **One DELETE policy and grant in the schema**: `instrument_records__delete__tenant_centre` (class E, system actor, `expires_at < now()`; 08 A17 D-65, P-18(c)). No other table has a DELETE policy or grant (classes C/A/M — 02-CV §5.6).
- G tables: no RLS, `SELECT` to `lims_app`, listed in `db/tests/rls_exempt.txt` with reason "global coded set, no tenant data".
- Device actors: C10 has no device-facing endpoint, and `pred_c` refuses device claims explicitly (`current_actor_type() IN ('user','system')`); `pred_t` admits them per P-16 (`is_staff_or_system()`), which only exposes configuration tables (device case tested in §10 item 8).

## 6. Published view `micro.v_pub_report_content` (03-IC §6.8 — column list is a contract)

CREATE VIEW micro.v_organisms WITH (security_invoker = true) AS
  SELECT t.code, t.display, t.sort_order, t.is_active, t.organism_group_code, t.gram_class, t.is_alert, t.snomed_ct_concept_id, 'tenant'::text AS source
  FROM micro.cs_organisms t WHERE t.tenant_id = (SELECT app.current_tenant_id())
  UNION ALL
  SELECT g.code, g.display, g.sort_order, g.is_active, g.organism_group_code, g.gram_class, g.is_alert, g.snomed_ct_concept_id, 'global'
  FROM micro.g_cs_organisms g
  WHERE NOT EXISTS (SELECT 1 FROM micro.cs_organisms t2 WHERE t2.tenant_id = (SELECT app.current_tenant_id()) AND t2.code = g.code);

LANGUAGE plpgsql SECURITY INVOKER SET search_path = '' AS $$

  IF EXISTS (SELECT 1 FROM micro.cultures c

END $$;
