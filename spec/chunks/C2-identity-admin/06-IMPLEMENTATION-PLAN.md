## 6. Risks and mitigations

| # | Risk | Likelihood / impact | Mitigation |
|---|---|---|---|
| R1 | Self-hosted GoTrue behaviour differs from hosted docs (MFA, links, refresh reuse) | M / H | T1 first; all calls behind `GoTrueGateway`; resolver design removes dependence on the access-token hook |
| R2 | Claims resolution on every request becomes a hotspot | L / H | one indexed DEFINER query; p95 budget 3 ms; load test at 500 rps; can add a 5-second per-instance cache keyed by session id **only** if measurements require (revocation latency then ≤ 5 s — would need founder sign-off) |
| R3 | Concurrent refresh triggers GoTrue reuse detection and logs users out | M / M | row lock in `resolveSession`; BFF cache; metric + alert `refresh_failed` |
| R4 | Step-up state used to lock out victims (DoS) | M / L | 60-min window, admin unlock, reset path; credential-stuffing alert |
| R5 | Support sessions perceived as vendor snooping | M / M | narrow allowlist (no PHI permissions), tenant banner, approval mode, full audit |
| R6 | Settings cache staleness (30 s) surprises admins | L / L | UI copy "Other screens update within 30 seconds"; security-lowering changes re-clamp sessions immediately |
| R7 | Mid-year fiscal pattern change breaks invoice series | L / H (IRD) | pending pattern effective next FY once `billing_live_on` is set (B6/L7) |
| R8 | Global email uniqueness leaks existence across tenants | M / L | generic message; rate tier; alert on spikes |
| R9 | Breached list missing in production | M / M | readiness check + alert; documented as release blocker in C1 runbook |
| R10 | Per-IP failure throttle (08 Addendum A1) slows a whole lab behind one NAT after ≥ 10 failed logins in 10 min | L / M | successful logins never counted; throttle only to 5/min for 30 min (not a block); thresholds are [CONV] config; admin notice + on-call alert make it visible; per-account limits unchanged |
| R11 | C0 CRs (004/005/009) and the 08 A25 core items land late → C2 cannot integrate | M / H | CRs filed first (day 1), unit/integration around interfaces; BFF flows tested with MSW |
| R12 | C0 delivers the A28 items late (`core.memberships.partner_role`, A28.5 `tg_row_audit` branch, R10 item-4 allowlist growth for A28.2) | M / H | build against fakes; T21, T25, T27, T31 integration waits on them; C2's A28.1/A28.4 DEFINERs are C2 SQL transcribed by C0 |
