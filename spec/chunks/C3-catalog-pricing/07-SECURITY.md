## 2. Assets and entry points

| Asset | Why it matters |
|---|---|
| A1 Reference ranges, critical limits, units, decimals, formulas | Wrong values silently mis-flag every future patient result (clinical safety); integrity is the top property |
| A2 Prices, surcharges, tax rules | Revenue integrity; mis-configured tax exposes the lab under VAT law (04 L5, L15, L25) |
| A3 Doctor and credit-party master incl. contacts | Personal data; referral attribution is commercially sensitive (04 L19) |
| A4 Instrument code maps | A wrong map writes an analyser value into the wrong analyte (clinical safety) |
| A5 Import/export files | Carry whole price lists / doctor contacts; uploads are untrusted parser input |
| A6 `catalog_revision` + events | Drive cache invalidation in C4/C5/C6/C7 |

| Entry point | Auth |
|---|---|
| E1 HTTP `/v1/catalog/*` (107 operations) via BFF | staff JWT (bearerJwt) + permission |
| E2 `CatalogPort` in-process | caller's `RequestContext` (tenant from verified claims) |
| E3 Worker tasks `catalog.*` | system actor with tenant from job payload written under RLS |
| E4 xlsx upload content | untrusted bytes |
| E5 C7 mapping UI (writes via E1) | staff JWT |
| E6 Seed migrations of `g_*` tables | C0 migration pipeline |

## 5. Personal data and logging rules

- C3 holds **no patient data**. Personal data = doctors' and credit parties' names/contacts (05-SCHEMA §3).
- Never logged, never in metrics labels, never in event payloads, never in problem `detail`: doctor/party names, phones, emails, registration numbers, notes, PAN, addresses, any xlsx cell value, formula sample inputs.
- Allowed in logs: ids, codes of orderables/analytes (non-personal), counts, revisions, import/export ids, issue codes.
- Import issue `message` is a fixed template per `issue_code` with column/row coordinates only.
- Files: stored in `catalog.files` (Nepal DB, backed up like other data — 04 S1, I2); uploads are never returned to clients; generated files are downloaded only by authorised users, each download in `access_log`.
- Port contact reads (`purpose:'notification'`) are counted; spikes alert.
- Exports with personal data (referrers) require privileged `catalog.referrer.export` (CR-C3-003).

## 8. Secrets

C3 uses **no secrets** of its own: no provider credentials, no API keys, no Supabase service key (02-CV §10.2 default "not used"), no Storage access (D-C3-05). It relies on the C0 core's verified JWT and DB login role `lims_api`/`lims_worker` (credentials managed by C1 per REQ-SEC-128). The optional malware-scan endpoint, if deployed, is configured by C0/C1, not by C3.
