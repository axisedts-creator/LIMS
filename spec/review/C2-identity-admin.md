## Needs lead decision

1. **#1 Pre-auth transaction and claims mechanism** for `loginStaff`, `loginPartner`, `openMobileSession`, `confirmEmailToken`, `requestPasswordRecovery` and every `bffSession` operation. C0 provides no transaction for public operations, and `withTenantScope` is not allowed there. One core API and an authz-guard exemption are needed (C0 + C2).
2. **#17 Idempotency store for platform-context operations.** `core.idempotency_keys.tenant_id` is NOT NULL, but C2 marks `provisionTenant`, `openSupportSession` and `invitePlatformStaff` `required`.
3. **#18 `withTenantScope` allowlist.** Either extend 08 R10.4 to the support-session and dead-letter-view operations, or move those logs to `identity.platform_events`.
4. **#19 Audit trigger on mixed tables** (`invitations`, `mfa_factors`, `ird_annex_records` with platform rows). Either `tg_row_audit` skips NULL-tenant rows and C2 writes `platform_events`, or the platform rows are split into separate tables.
5. **#23 A1 "alert the tenant admins of every targeted tenant".** It needs an email-to-tenant DEFINER and a worker fan-out, or a narrower requirement.
6. **#24 Patient session kind.** GoTrue has no verified way to create credential-less users or sessions. Choose between T1-verified GoTrue admin calls and LIMS-issued JWTs (08 R10 change).
7. **#25 Client IP on non-BFF public identity routes** (mobile, patient). This needs a C0/C1 trusted-proxy rule; D-32 currently falls back to the peer address, which is nginx.
8. **#20 Annex readiness visibility.** Choose between a narrow tenant SELECT policy on the referenced platform Annex 1 row and a denormalised status column.
9. **#26 Recovery-link TTL fallback.** Either add a recovery-request table or declare "GoTrue TTL configurable" a release precondition (CR to C1).
10. **#57 Re-inviting former staff of another tenant.** Allow it, or record the restriction as a client question.
11. **#6 / #52 program-doc follow-ups.** IC §4.6 still shows `expectedVersion: number` (D-100 not applied), and the IC §11 `partner_member` set lacks `identity.self.manage` (D-101 not applied; IC l.2942). CM §5.1 lacks `getStaffNotificationContact`.
